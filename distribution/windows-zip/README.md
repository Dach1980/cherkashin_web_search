# Коммерческий комплект Web Search для LM Studio — Windows ZIP

> Рабочая папка подготовки продукта. Это спецификация и план выпуска, а не готовый дистрибутив. До прохождения проверок ниже продукт нельзя считать готовым к продаже.

## 1. Зафиксированное решение

Первый коммерческий выпуск распространяется **обычным ZIP-архивом**. Полноценный установщик Windows `.exe` на первом этапе **не разрабатываем**.

Покупатель не должен устанавливать Python, VS Code, PowerShell, Git или другие инструменты разработки и не должен вводить команды. Все действия выполняются через Проводник Windows и графический интерфейс LM Studio.

Целевой сценарий:
1. Скачать ZIP из платного поста Boosty.
2. Распаковать его стандартной функцией Windows «Извлечь всё…».
3. Переместить распакованную папку в постоянное место.
4. Открыть встроенный редактор MCP-конфигурации LM Studio.
5. Добавить запись нашего MCP-сервера в существующий `mcp.json`, сохранив другие серверы и настройки.
6. Сохранить конфигурацию и проверить оба инструмента.

Первичная целевая платформа — Windows 10/11 x64. Совместимость с конкретными версиями Windows и LM Studio должна быть подтверждена тестами перед публикацией.

## 2. Назначение папки

В `distribution/windows-zip/` хранятся материалы именно коммерческого Windows ZIP-продукта:
- требования к комплекту и структуре архива;
- пользовательские инструкции;
- шаблон конфигурации MCP;
- сведения о версии и выпуске;
- чек-листы сборки, проверки и публикации.

Исходный код MCP-сервера остаётся в `src/web_search_mcp/`, учебные материалы — в `lessons/`, техническая точка входа PyInstaller — в `packaging/`. Эта папка не заменяет исходный проект и не дублирует серверную реализацию.

Собранные бинарные файлы и финальные архивы добавляются сюда только после реальной сборки и тестирования. Не коммитить временные файлы сборки, кэши, логи, секреты и пользовательские конфигурации.

## 3. Предполагаемая структура ZIP

Имя будущего архива: `Web_Search_for_LM_Studio_Windows_v1.0.zip`.

Ожидаемая структура после распаковки (окончательные имена EXE и папок определяются по фактической сборке):

```text
Web_Search_for_LM_Studio/
├── WebSearchServer/
│   ├── <фактическое-имя-сервера>.exe
│   ├── <вспомогательные-файлы-и-библиотеки>
│   └── ...
├── LM_Studio_Config/
│   └── mcp_config_example.json
├── Инструкция/
│   ├── 01_Распаковка-и-размещение.pdf
│   ├── 02_Подключение-к-LM-Studio.pdf
│   └── 03_Проверка-работы.pdf
├── README.txt
└── VERSION.txt
```

Для режима PyInstaller `onedir` передаётся **вся папка сборки целиком**, а не один EXE. Не переименовывать и не удалять внутренние файлы, если это нарушает структуру PyInstaller.

В репозитории допустимо хранить редактируемые исходники инструкций и шаблоны. Готовый архив и бинарные артефакты добавляются только после принятия решения о способе их хранения и проверки размера/лицензионных условий зависимостей.

## 4. Установка глазами покупателя

### Шаг 1. Скачать
Покупатель скачивает ZIP, приложенный к оплаченному посту Boosty.

### Шаг 2. Распаковать
В Проводнике Windows: правая кнопка по ZIP → «Извлечь всё…» → «Извлечь».

### Шаг 3. Выбрать постоянное место
Рекомендуемое расположение:
`Документы\LM Studio\Web Search`

Папка должна оставаться на месте после настройки LM Studio. Не следует размещать комплект во временной папке загрузок, если пользователь планирует её очищать.

### Шаг 4. Подключить MCP
В LM Studio открыть раздел управления MCP (в проверенной на момент подготовки версии интерфейса: Program → Install → Edit mcp.json). Добавить запись сервера в существующий JSON, указав абсолютный путь к EXE в распакованной папке.

**Критически важно:** не предлагать заменять весь `mcp.json`. Пользователь может уже иметь другие MCP-серверы. Инструкция должна показывать, как добавить только одну запись внутрь существующего объекта `mcpServers`, либо как создать его, если его ещё нет. Нужно объяснить корректное расположение запятых и проверить итоговый JSON.

Путь у каждого покупателя свой. Нельзя выдавать один заранее заполненный абсолютный путь как универсальный. Шаблон должен явно помечать значение, которое покупатель заменяет на свой путь. Перед публикацией проверить синтаксис примера и соответствие формата актуальной версии LM Studio.

### Шаг 5. Проверить
После сохранения конфигурации проверить, что LM Studio загрузила сервер и показывает оба инструмента:
- `search_web`;
- `fetch_web_page`.

Затем выполнить реальный запрос поиска и загрузить содержимое публичной веб-страницы.

## 5. Требования к пользовательским материалам

Инструкции пишутся для обычного пользователя Windows, без предположения о технических знаниях.

Обязательные свойства:
- русский язык;
- короткие последовательные шаги;
- скриншот каждого важного действия в Проводнике и LM Studio;
- точные названия пунктов интерфейса для проверенной версии LM Studio;
- отдельное объяснение, как сохранить существующие MCP-записи;
- пример правильного JSON и примеры частых ошибок;
- указание, где находится EXE и как скопировать его путь через Проводник;
- инструкция проверки каждого инструмента;
- раздел «Что делать, если сервер не появился»;
- предупреждение, что после перемещения папки нужно обновить путь в `mcp.json`.

Запрещено требовать от покупателя:
- запускать PowerShell, CMD или Windows Terminal;
- устанавливать Python или библиотеки;
- открывать VS Code;
- клонировать Git-репозиторий;
- собирать EXE самостоятельно;
- вручную запускать команды для установки.

## 6. Технические требования к сборке

Предварительный вариант — PyInstaller `onedir` с консольными каналами (`--console`), так как MCP использует stdio. Это пока план сборки, а не подтверждённый готовый бинарный пакет.

До выпуска необходимо:
1. Проверить актуальную точку входа и фактическую реализацию сервера.
2. Проверить реальные имена MCP-инструментов в исходниках и через LM Studio.
3. Проверить зависимости, динамические импорты и ресурсы библиотек.
4. Убедиться, что stdout не загрязняется отладочными сообщениями: он используется MCP-протоколом. Диагностика должна идти в stderr или безопасный лог.
5. Зафиксировать версии Python, PyInstaller и зависимостей, использованных при сборке.
6. Собрать пакет на Windows x64.
7. Проверить запуск собранного приложения из LM Studio, а не только наличие EXE.
8. Убедиться, что в комплект не попали секреты, локальные файлы окружения и лишние файлы разработки.

Наличие EXE само по себе не доказывает переносимость или работоспособность. Не обещать поддержку других ОС, пока для них не подготовлены отдельные сборки и проверки.

## 7. Проверка «как покупатель»

Это обязательный release gate. Платный пост Boosty нельзя публиковать до завершения проверки.

Тестировать не из каталога разработки и не с использованием Python-окружения проекта, а из новой чистой папки, используя только готовый ZIP и обычный интерфейс Windows.

- [ ] Собран дистрибутив Windows x64.
- [ ] ZIP создан из полного каталога сборки.
- [ ] ZIP распакован через Проводник Windows в новую чистую папку.
- [ ] Комплект перемещён в постоянный каталог.
- [ ] LM Studio настроена через GUI, без командной строки.
- [ ] Существующие записи `mcp.json` сохранены.
- [ ] Конфигурация корректна и сервер загружен.
- [ ] `search_web` реально вызван и вернул ожидаемый результат.
- [ ] `fetch_web_page` реально вызван и вернул содержимое публичной страницы.
- [ ] После перезапуска LM Studio сервер подключается снова.
- [ ] Проверено поведение при неверном пути и описано понятное исправление.
- [ ] Проверено, что покупателю не нужны Python, VS Code и терминал.
- [ ] Записаны точные версии Windows и LM Studio, на которых проведён тест.
- [ ] Зафиксированы версия комплекта и SHA-256 финального ZIP.

Если чистый тест не пройден, выпуск не публикуется. Нельзя отмечать пункты выполненными только на основании автоматических тестов исходного Python-кода.

## 8. Границы продукта и честное описание

Планируемое позиционирование: «Готовый Web Search для LM Studio — подключите поиск в интернете к своей локальной модели».

До публикации явно описать:
- поддерживаемую платформу и проверенную версию LM Studio;
- необходимость подключения к интернету;
- что качество ответов зависит также от выбранной модели;
- что доступность и содержимое сайтов могут ограничивать поиск и загрузку страниц;
- что это MCP-сервер, а не отдельная поисковая модель;
- какие инструменты входят в комплект.

Не обещать безусловный доступ ко всем сайтам, гарантированную достоверность результатов или совместимость со всеми версиями LM Studio.

8. Только после успешной проверки подготовить бесплатный рекламный и платный посты Boosty.

## 10. Отложенные улучшения

Автоматический установщик `.exe`, который копирует файлы в пользовательский каталог и безопасно изменяет `mcp.json`, **не входит в первый выпуск**. Вернуться к нему можно после проверки спроса и получения обратной связи от покупателей.

Также отдельно можно рассмотреть обновление продукта, цифровую подпись бинарного файла и дополнительные платформы. Эти функции не должны задерживать простой ZIP-релиз, но требования безопасности и корректности обязательны уже сейчас.
