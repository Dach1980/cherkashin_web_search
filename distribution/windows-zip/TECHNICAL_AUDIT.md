## 2. Что обнаружено в коде

### 2.1 MCP-сервер и инструменты

Файл: `src/web_search_mcp/server.py`

- Используется `FastMCP` из `mcp.server.fastmcp`.
- Транспорт запускается как `stdio` через `mcp.run(transport="stdio")`.
- Точка входа `main()` существует; `packaging/launcher.py` импортирует и вызывает её.
- В коде зарегистрированы инструменты с фактическими именами **`search_web`** и **`fetch_web_page`**.
- Функции инструментов возвращают структурированные словари с фиксированными полями.
- Логирование настроено на `sys.stderr`, что правильно для stdio MCP: диагностический текст не должен засорять stdout.

**Важно для выпуска:** в ряде документов и старых материалов указаны другие имена — `web_search` и `web_fetch`. Пользовательские инструкции, тестовые запросы и описание продукта должны использовать реальные имена `search_web` и `fetch_web_page`.

### 2.2 Поиск

Файл: `src/web_search_mcp/web_search.py`

- Используется HTML-страница DuckDuckGo: `https://html.duckduckgo.com/html/`.
- Запрос передаётся через HTTPX; есть тайм-аут и проверка HTTP-ошибок.
- Число результатов ограничено диапазоном 1–10.
- HTML разбирается Beautiful Soup по CSS-селекторам DuckDuckGo.
- Ошибки HTTPX преобразуются в структурированный ответ, а не выбрасываются наружу.

Ограничения и риски:
- Поиск зависит от доступности DuckDuckGo, сетевых условий, антибот-защиты и текущей HTML-разметки. CSS-селекторы могут перестать соответствовать странице.
- В этой функции нет автоматического резервного поискового провайдера.
- Не обнаружено ограничения размера HTML-ответа поисковой страницы.
- Автоматические тесты проверяют разбор подставленного HTML, но не подтверждают реальную выдачу DuckDuckGo на момент использования.

Это допустимо для первой версии при честном описании зависимости от внешнего сервиса, но реальные сетевые проверки обязательны.

### 2.3 Загрузка страниц и безопасность URL

Файл: `src/web_search_mcp/web_fetch.py`

Положительные меры:
- разрешены только HTTP/HTTPS;
- отклоняются URL с учётными данными;
- блокируются localhost и некоторые локальные домены;
- проверяются IP-адреса, полученные DNS-разрешением;
- отклоняются не глобальные IP-адреса;
- редиректы обрабатываются вручную и повторно валидируются;
- число редиректов ограничено;
- ограничен размер ответа в байтах;
- проверяется HTML/XHTML content type;
- ограничена длина возвращаемого текста;
- ошибки не раскрывают текст исключений HTTPX.

**Существенный риск — DNS rebinding / TOCTOU.** Код сначала выполняет DNS-проверку через `socket.getaddrinfo()`, а затем HTTPX самостоятельно разрешает имя хоста при соединении. Между этими действиями DNS-ответ может измениться. Поэтому проверка DNS в текущем виде не является строгой гарантией, что фактическое соединение будет установлено только с проверенным публичным IP. Автотесты прямо не проверяют эту угрозу.

До коммерческого выпуска нужно отдельно решить и протестировать защиту от DNS rebinding. Варианты требуют инженерного выбора: например, закрепление проверенного IP на время соединения с сохранением исходного Host/SNI и корректной TLS-проверки, либо другой проверенный механизм безопасного соединения. Нельзя просто отключить TLS-проверку или считать повторную проверку перед запросом достаточным решением.

Дополнительные замечания:
- для DNS-проверки используется системный resolver; поведение может отличаться в разных сетевых окружениях;
- тесты подменяют функцию URL-валидации во многих успешных сценариях, поэтому не доказывают корректность настоящей DNS-проверки;
- проверка редиректа на loopback покрывает полезный сценарий, но не DNS rebinding;
- следует добавить отдельные тесты на IPv4/IPv6, смешанные DNS-ответы (публичный + приватный), локальные домены и перенаправления на запрещённые адреса.

### 2.4 Конфигурация

Файл: `src/web_search_mcp/config.py`

Фактические переменные окружения:
- `WEB_TIMEOUT_SECONDS` — тайм-аут, по умолчанию 15 секунд;
- `WEB_SEARCH_MAX_RESULTS` — максимум результатов поиска, по умолчанию 5;
- `WEB_FETCH_MAX_PAGE_CHARS` — лимит текста страницы, по умолчанию 12 000 символов;
- `WEB_FETCH_MAX_REDIRECTS` — число редиректов, по умолчанию 3;
- `WEB_FETCH_MAX_RESPONSE_BYTES` — максимальный размер ответа, по умолчанию 1 000 000 байт;
- `WEB_SEARCH_LOG_LEVEL` — уровень логирования, по умолчанию INFO.

Числовые параметры проверяются на диапазон при импорте модуля. Некорректное значение переменной окружения может помешать запуску всего MCP-сервера — это ожидаемое поведение валидации, но сообщение об ошибке должно быть доступно для диагностики.

**Несоответствие:** `.env.example` содержит старые/неиспользуемые имена вроде `REQUEST_TIMEOUT_SECONDS`, `MAX_SEARCH_RESULTS`, `MAX_PAGE_CHARS` и не отражает фактическую конфигурацию. Кроме того, в зависимостях нет явного загрузчика dotenv; не следует обещать, что файл `.env` автоматически читается. Для коммерческого ZIP лучше дать понятные настройки через поле `env` в MCP-конфигурации LM Studio, только если покупателю вообще потребуется их менять. Для первого выпуска можно использовать безопасные значения по умолчанию.

### 2.6 Тесты

Найдено 18 тестовых функций:

Проверяются в том числе пустой запрос, некорректный лимит, разбор подставленного HTML, HTTP-ошибки, loopback URL, неподдерживаемая схема, редирект на loopback, превышение размера ответа, ограничение длины текста.

Но:

- нет теста регистрации инструментов и их точных имён через MCP SDK;

- нет теста запуска упакованного EXE;
- нет теста запуска на чистой Windows-машине;
- нет теста DNS rebinding;
- тесты не доказывают доступность сайтов и устойчивость поискового HTML-парсера.

В `tests/README.md` прямо отмечено, что unit-тесты не заменяют MCP-интеграцию и не гарантируют защиту от DNS rebinding.

## 4. Проверка идеи PyInstaller

По исходникам есть подходящая точка входа `packaging/launcher.py`, вызывающая `web_search_mcp.server.main()`. Это разумная основа для PyInstaller.

Однако команда из урока 19 пока является **гипотезой сборки**, а не проверенной инструкцией:
- динамические импорты и ресурсы MCP SDK могут потребовать дополнительных настроек;
- версия `mcp` не зафиксирована;
- не проверено, что собранный каталог запускается на другой Windows-машине;
- необходимо подтвердить сохранение stdio-поведения в собранном приложении;
- каталог `onedir` нужно передавать целиком.

Рекомендация: начинать с `onedir` + консольный режим, но не объявлять команду сборки окончательной до реального теста на Windows.
