## 1. Зачем нужны условия

Представим, что будущий инструмент получает поисковый запрос. Если пользователь передал пустую строку, отправлять её поисковому сервису бессмысленно. Сначала нужно проверить входные данные, а затем либо продолжить работу, либо сообщить об ошибке.

**Условие** — конструкция, которая позволяет программе выбирать, какие команды выполнить, в зависимости от истинности проверки. Без условий программа обычно идёт по командам последовательно; с условиями она может выбирать разные пути.

## 2. Операторы сравнения

**Оператор** — специальный символ или слово, обозначающее действие над значениями. В предыдущем уроке мы использовали `=` для присваивания. Теперь познакомимся с операторами сравнения.

| Оператор | Значение | Пример | Результат |
|---|---|---|---|
| `==` | равно | `5 == 5` | `True` |
| `!=` | не равно | `5 != 3` | `True` |
| `>` | больше | `5 > 3` | `True` |
| `<` | меньше | `2 < 7` | `True` |
| `>=` | больше или равно | `5 >= 5` | `True` |
| `<=` | меньше или равно | `4 <= 3` | `False` |

Два знака равенства `==` сравнивают значения, а один знак `=` присваивает значение переменной.

~~~
max_search_results = 5

print(max_search_results == 5)
print(max_search_results == 10)
print(max_search_results != 0)
~~~

Результат:

~~~
True
False
True
~~~

В первой строке мы создаём переменную. Затем сравниваем её значение с пятью и десятью. Сравнение возвращает логическое значение `True` или `False`, но само по себе не меняет переменную.

### Проверяем длину строки

Встроенная функция `len()` возвращает длину объекта; для строки — количество символов.

~~~
query = "документация MCP"
print(len(query) > 0)
~~~

Выражение `len(query) > 0` проверяет, содержит ли строка хотя бы один символ. Результат — `True`. Эта проверка пригодится для первичной проверки пользовательского запроса.

## 3. Конструкция `if` — «если»

Ключевое слово `if` означает «если». Оно начинает условие, после которого через двоеточие `:` записывается блок команд. Блок выделяется отступом, обычно четырьмя пробелами.

~~~
query = "документация Python"

if len(query) > 0:
    print("Запрос не пустой")
~~~

Python проверяет условие. Если результат `True`, выполняется строка с отступом. Если `False` — блок пропускается.

Проверим пустой запрос:

~~~
query = ""

if len(query) > 0:
    print("Запрос не пустой")

print("Проверка завершена")
~~~

Результат:

~~~
Проверка завершена
~~~

Сообщение о непустом запросе не появилось, потому что длина пустой строки равна нулю. Последний `print()` расположен без отступа и потому находится вне блока `if` — он выполняется в любом случае.

**Важно:** отступы в Python — часть синтаксиса. Неверный отступ может привести к ошибке или изменить логику программы.

## 4. Альтернативная ветка `else`

`else` означает «иначе». Она описывает, что делать, если условие `if` ложно.

~~~
query = ""

if len(query) > 0:
    print("Запрос принят")
else:
    print("Ошибка: введите поисковый запрос")
~~~

Результат: `Ошибка: введите поисковый запрос`.

Программа выбирает одну из двух веток. Это яснее, чем писать одну и ту же проверку дважды.

## 5. Несколько вариантов с `elif`

`elif` — сокращение от *else if*, «иначе если». Используйте его, если вариантов больше двух.

~~~
result_count = 0

if result_count == 0:
    print("Поиск не вернул результатов")
elif result_count < 3:
    print("Найдено мало результатов")
else:
    print("Результатов достаточно для примера")
~~~

Результат:

~~~
Поиск не вернул результатов
~~~

Python проверяет ветки сверху вниз. Как только одно условие истинно, выполняется его блок, а остальные ветки пропускаются. `else` выполняется, только если предыдущие условия не сработали.

## 6. Логические операторы `and`, `or` и `not`

Когда одной проверки недостаточно, несколько условий можно объединить логическими операторами.

### `and` — «И»

`and` возвращает истинный результат, только если истинны обе части.

~~~
query = "документация MCP"
max_results = 5

if len(query) > 0 and max_results > 0:
    print("Входные данные прошли простую проверку")
~~~

Программа проверяет одновременно, что запрос непустой и лимит результатов положительный. Если хотя бы одно условие ложно, вся проверка с `and` ложна.

Используйте `and`, когда необходимо выполнить несколько требований одновременно.

### `or` — «ИЛИ»

`or` даёт истинный результат, если истинна хотя бы одна часть.

~~~
status_code = 404

if status_code == 404 or status_code == 410:
    print("Страница не найдена или больше недоступна")
~~~

Для учебного примера мы объединяем два статуса. Сообщение появится, если код равен 404 **или** 410. Используйте `or`, когда разные ситуации требуют одинаковой реакции.

### `not` — «НЕ»

`not` меняет логическое значение на противоположное: `not True` даёт `False`, а `not False` даёт `True`.

~~~
query = ""

if not query:
    print("Запрос отсутствует")
~~~

Пустая строка в логическом контексте считается ложной, поэтому `not query` становится истинным.

В Python пустые строки, пустые списки, ноль и `None` считаются ложными в условии. Непустые строки и списки, а также ненулевые числа обычно считаются истинными. Это свойство называют *truthiness* — условная истинность значения.

Для проверки пустого текста допустимы оба варианта: `if not query:` и `if len(query) == 0:`. Выбирайте наиболее понятную форму.

### Таблица истинности

| A | B | `A and B` | `A or B` |
|---|---|---|---|
| `True` | `True` | `True` | `True` |
| `True` | `False` | `False` | `True` |
| `False` | `True` | `False` | `True` |
| `False` | `False` | `False` | `False` |

### Короткое замыкание

*Short-circuit evaluation* — вычисление с коротким замыканием. Если в выражении `A and B` часть `A` уже ложна, Python не обязан вычислять `B`: общий результат всё равно ложен. Для `A or B`, если `A` уже истинна, вычислять `B` не нужно.

Это может повышать эффективность и помогает писать проверки в правильном порядке. Но короткое замыкание не заменяет полноценную защиту сетевых запросов: URL, перенаправления и DNS в нашем проекте потребуют отдельной проверки.

## 7. Скобки и сложные условия

Если условие становится сложным, используйте скобки, чтобы группировка была очевидной.

~~~
query = "MCP"
max_results = 5
is_enabled = True

if is_enabled and (len(query) > 0 or max_results > 0):
    print("Пример прошёл проверку")
~~~

Сначала вычисляется выражение в скобках: достаточно, чтобы хотя бы одна из двух проверок была истинной. Затем внешний `and` требует, чтобы `is_enabled` тоже был истинным.

Не пытайтесь помещать всю сложную логику в одну строку. Позже часть проверок можно вынести в функции с понятными именами.

## 8. Что такое функция

**Функция** — именованный блок кода, который выполняет определённую задачу и может использоваться многократно. Мы уже вызывали встроенные функции `print()`, `len()` и `type()`. Теперь научимся создавать собственные.

Функции полезны, потому что:
- повторяющуюся логику можно написать один раз;
- имя функции объясняет её назначение;
- отдельную функцию проще тестировать;
- основной код становится короче и понятнее;
- одну функцию можно применять в нескольких местах проекта.

В будущем отдельными функциями будут проверка запроса, поиск страниц и извлечение текста из страницы.

## 9. Определяем функцию с помощью `def`

`def` — сокращение от английского *define*, «определить». Это ключевое слово начинает определение функции.

~~~
def show_welcome():
    print("Добро пожаловать в курс Python")

show_welcome()
~~~

Разбор:
1. `def` начинает определение.
2. `show_welcome` — имя функции.
3. Пустые скобки `()` означают, что функция пока не принимает параметры.
4. Двоеточие `:` начинает тело функции.
5. Строка с отступом — команда, которая выполнится при вызове.
6. `show_welcome()` вызывает функцию.

**Определение функции не выполняет её тело.** Оно сообщает Python, как выполнить функцию, когда её вызовут. Поэтому сообщение появляется только после вызова `show_welcome()`.

Скобки важны: `show_welcome()` — вызов, а `show_welcome` без скобок — ссылка на сам объект функции.

## 10. Параметры и аргументы

**Параметр** — имя в определении функции, через которое она получает входное значение. **Аргумент** — конкретное значение, переданное функции при вызове.

~~~
def greet_user(name):
    print(f"Здравствуйте, {name}!")

greet_user("Анна")
greet_user("Иван")
~~~

`name` — параметр. Строки `"Анна"` и `"Иван"` — аргументы.

Результат:

~~~
Здравствуйте, Анна!
Здравствуйте, Иван!
~~~

Функция одна, но её можно вызывать с разными данными. Это повторное использование кода.

Функция с двумя параметрами:

~~~
def show_search_settings(query, max_results):
    print(f"Поисковый запрос: {query}")
    print(f"Максимум результатов: {max_results}")

show_search_settings("документация MCP", 5)
~~~

Первый аргумент передаётся в `query`, второй — в `max_results`. При обычной позиционной передаче порядок важен. Поэтому выбирайте для параметров понятные имена.

## 11. Возвращаем результат с помощью `return`

До сих пор функции выводили сообщения через `print()`. Но другой участок программы часто должен получить результат и использовать его дальше. Для этого предназначено ключевое слово `return` — «вернуть».

~~~
def get_query_length(query):
    return len(query)

length = get_query_length("документация MCP")
print(length)
~~~

Последовательность действий:
1. Функция получает строку в параметре `query`.
2. `len(query)` вычисляет длину.
3. `return` возвращает число туда, где функцию вызвали.
4. Результат сохраняется в переменной `length`.
5. `print(length)` показывает число в терминале.

**Главное отличие:** `print()` показывает информацию человеку, а `return` передаёт результат вызывающему коду. Эти действия не взаимозаменяемы.

Рассмотрим ошибочный с точки зрения возврата результата вариант:

~~~
def get_query_length_wrong(query):
    print(len(query))

result = get_query_length_wrong("MCP")
print(result)
~~~

Вывод:

~~~
3
None
~~~

Число 3 печатается внутри функции. Но явного `return` нет, поэтому функция возвращает `None`. Именно это значение получает переменная `result`.

Правильный вариант:

~~~
def get_query_length(query):
    return len(query)

result = get_query_length("MCP")
print(result)
~~~

Результат: `3`.

### Почему `return` важен для MCP

Функция `web_search` должна не просто напечатать ссылки в терминале. Она должна вернуть результат, чтобы MCP-сервер передал его вызывающей модели. Аналогично, загрузчик страницы должен возвращать текст или понятный результат ошибки. Поэтому вычисление результата следует отделять от диагностического вывода.

## 12. Возвращаем разные результаты в зависимости от условия

Условия и функции хорошо работают вместе. Создадим функцию, которая проверяет, не пуст ли запрос.

~~~
def validate_query(query):
    if not query:
        return "Ошибка: поисковый запрос пустой"

    return "Запрос принят"

print(validate_query(""))
print(validate_query("документация MCP"))
~~~

Результат:

~~~
Ошибка: поисковый запрос пустой
Запрос принят
~~~

`validate` — английское «проверять на соответствие требованиям». Функция `validate_query` проверяет входные данные.

Если `query` пуст, выполняется первый `return`. Он немедленно завершает текущий вызов функции. Если первый `return` не сработал, выполнение доходит до второго и возвращает сообщение об успешной проверке.

Такой стиль помогает быстро завершать функцию при обнаружении ошибки. Пока мы возвращаем текст, потому что ещё не изучили структуры данных для формализованного результата.

## 13. Проверяем несколько условий внутри функции

Добавим проверку запроса и лимита результатов.

~~~
def validate_search_input(query, max_results):
    if not query:
        return "Ошибка: введите поисковый запрос"

    if max_results <= 0:
        return "Ошибка: лимит результатов должен быть больше нуля"

    return "Входные данные корректны"


print(validate_search_input("документация MCP", 5))
print(validate_search_input("", 5))
print(validate_search_input("документация MCP", 0))
~~~

Результат:

~~~
Входные данные корректны
Ошибка: введите поисковый запрос
Ошибка: лимит результатов должен быть больше нуля
~~~

Оператор `<=` означает «меньше или равно». Проверка `max_results <= 0` отклоняет нулевой и отрицательный лимит.

Функция выполняет проверки по порядку. Если запрос пуст, срабатывает первый `return`, и дальнейшая проверка для этого вызова не выполняется. Если запрос непустой, функция переходит к проверке лимита.

Это только учебная проверка. Позже дополнительно проверим тип входных данных и максимальный допустимый лимит. Для URL нужна отдельная, более серьёзная логика безопасности.

## 14. Область видимости переменных

**Область видимости** (*scope*) — часть программы, в которой имя доступно для использования.

~~~
server_name = "web-search-mcp"

def show_server_name():
    message = f"Имя сервера: {server_name}"
    print(message)

show_server_name()
~~~

Функция читает переменную `server_name`, объявленную снаружи. В этом примере это работает, потому что функция использует внешнее имя, а не присваивает ему новое значение.

Теперь локальная переменная:

~~~
def make_message():
    message = "Проверка завершена"
    return message

result = make_message()
print(result)
~~~

`message` создана внутри функции и используется там. Снаружи мы сохраняем возвращённое значение в `result`.

Понятные локальные переменные помогают избежать случайных зависимостей между функциями. В нашем проекте будем передавать данные через параметры и возвращать результаты через `return`, а не полагаться на множество изменяемых глобальных переменных.

## 15. Мини-проект: проверяем поисковый запрос

Создайте файл `lesson_04.py` в корне репозитория `cherkashin_web_search` и вставьте код:

~~~
def validate_search_input(query, max_results):
    """Проверяет базовые параметры поискового запроса."""

    if not query:
        return "Ошибка: поисковый запрос не должен быть пустым"

    if max_results <= 0:
        return "Ошибка: количество результатов должно быть больше нуля"

    return "Входные данные прошли базовую проверку"


def show_check_result(query, max_results):
    result = validate_search_input(query, max_results)
    print(f"Запрос: {query!r}")
    print(f"Лимит результатов: {max_results}")
    print(f"Результат проверки: {result}")
    print("-" * 40)


show_check_result("документация MCP", 5)
show_check_result("", 5)
show_check_result("Python web search", 0)
~~~

### Разбор кода

**Функция `validate_search_input(query, max_results)`** принимает текст запроса и лимит. Она проверяет, что запрос непуст и лимит положительный. Функция возвращает сообщение, но не печатает его сама. Благодаря этому проверку можно использовать из другой части программы.

**Строка документации.** Строка `"""Проверяет базовые параметры поискового запроса."""` — краткое описание функции. Её называют *docstring*. Документация помогает разработчикам и инструментам документации понять назначение функции. Это не комментарий с `#`.

**`query!r` внутри f-строки.** Запись `{query!r}` использует специальное преобразование `!r`: Python показывает представление значения, удобное для отладки. Для пустой строки видны кавычки `''`, и легче заметить, что запрос действительно пуст. Для обычного вывода можно использовать `{query}`.

**`"-" * 40`.** Оператор `*` здесь повторяет строку 40 раз и создаёт горизонтальный разделитель. Для чисел `*` выполняет умножение, а для строки и целого числа — повторение строки.

## 16. Типичные ошибки начинающих

### Ошибка 1. Забыли двоеточие

Неправильно:

~~~
if max_results > 0
    print("Лимит допустим")
~~~

Правильно:

~~~
if max_results > 0:
    print("Лимит допустим")
~~~

### Ошибка 2. Нет отступа

Неправильно:

~~~
if max_results > 0:
print("Лимит допустим")
~~~

Строка `print()` должна иметь отступ, поскольку относится к телу условия.

### Ошибка 3. Использовали `=` вместо `==`

Для проверки нужно написать:

~~~
if max_results == 5:
    print("Лимит равен пяти")
~~~

Один знак равенства предназначен для присваивания, два — для сравнения.

### Ошибка 4. Функцию определили, но не вызвали

`def show_welcome(): ...` описывает функцию, но не запускает её тело. Для выполнения нужен вызов `show_welcome()`.

### Ошибка 5. Перепутали `print()` и `return`

`print()` отображает информацию в терминале. `return` возвращает значение вызывающему коду. Если результат нужен другой функции, его обычно следует вернуть.

### Ошибка 6. Неправильное количество аргументов

Если функция определена как `def greet_user(name):`, обычный вызов должен передать один аргумент: `greet_user("Анна")`. Если забыть аргумент, Python сообщит об ошибке вызова.

### Ошибка 7. Слишком сложное условие

Если условие трудно читать, разбейте проверку на несколько шагов или вынесите её часть в отдельную функцию. Читаемость важнее того, чтобы уместить всю логику в одну строку.
