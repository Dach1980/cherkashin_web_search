Теперь переходим к сетевому взаимодействию: научимся отправлять запросы веб-сайтам, получать ответы и обрабатывать ошибки. Это основа для будущих инструментов нашего Python MCP-сервера для LM Studio: web_search и web_fetch.

## 2. Термины, которые понадобятся

**HTTP (Hypertext Transfer Protocol — протокол передачи гипертекста)** — набор правил, по которым клиент и сервер обмениваются запросами и ответами. HTTP используется не только для HTML-страниц, но и для JSON и других данных.

**HTTPS** — HTTP поверх защищённого соединения TLS. Он помогает защитить данные при передаче и проверить подлинность сервера. Обычно следует предпочитать HTTPS.

**Клиент** — программа, которая инициирует запрос. В нашем случае клиент — Python-программа. **Сервер** — программа, которая принимает запрос и возвращает ответ.

**URL (Uniform Resource Locator — унифицированный указатель ресурса)** — адрес ресурса, например https://example.com/. Он включает схему (https), имя узла (example.com) и, возможно, путь.

**Запрос (request)** — сообщение от клиента серверу. **Ответ (response)** — сообщение сервера клиенту. Ответ обычно содержит статус-код, заголовки и тело.

**GET** — HTTP-метод, который обычно используют для получения ресурса. **Заголовки (headers)** — дополнительные сведения о запросе или ответе. **Тело ответа (response body)** — переданные данные, например HTML-код страницы.

**Статус-код (status code)** — число, обозначающее результат HTTP-запроса. Примеры: 200 — успех; 301/302 — перенаправление; 400 — некорректный запрос; 401 — требуется аутентификация; 403 — доступ запрещён; 404 — ресурс не найден; 429 — слишком много запросов; 500 — внутренняя ошибка сервера; 503 — сервис временно недоступен.

**Библиотека** — готовый код, который можно использовать в своей программе. **httpx** — библиотека Python для HTTP-запросов.

**Тайм-аут (timeout)** — ограничение времени ожидания. Он не позволяет сетевой операции бесконечно задерживать программу.

**Исключение (exception)** — объект Python, сообщающий об ошибочной или необычной ситуации во время выполнения. Исключения можно обработать, чтобы контролируемо отреагировать на сбой.

## 3. Как проходит HTTP-запрос

1. Python-программа получает URL.
2. Библиотека пытается установить соединение.
3. Программа отправляет GET-запрос.
4. Сервер обрабатывает его и возвращает статус, заголовки и тело.
5. Программа проверяет ответ и решает, что делать дальше.

На любом этапе может возникнуть проблема. Например, соединение может не установиться, сервер может отвечать слишком долго или вернуть статус 404.

Важно различать **сетевую ошибку** и **HTTP-ошибку**. При сетевой ошибке запрос не удалось нормально выполнить: например, соединение не установилось или истёк тайм-аут. При HTTP-ошибке сервер ответил, но сообщил о неуспешном результате, например 404 или 503.

## 4. Установка httpx

Откройте проект в Visual Studio Code и активируйте виртуальное окружение, созданное в уроке 6. В терминале PowerShell выполните:

~~~powershell
python -m pip install httpx
~~~

Разбор команды:
- python запускает интерпретатор;
- параметр -m просит Python запустить модуль как программу;
- pip — инструмент установки пакетов;
- install — команда установки;
- httpx — устанавливаемый пакет.

Почему используем python -m pip, а не просто pip? Это связывает установку с тем интерпретатором Python, который запустил команду. На компьютере может быть установлено несколько версий Python, и отдельная команда pip иногда относится не к той версии.

Проверьте установку:

~~~powershell
python -c "import httpx; print(httpx.__version__)"
~~~

Параметр -c означает «выполнить код, переданный строкой». import подключает библиотеку, print выводит её версию, а __version__ — атрибут библиотеки с номером версии.

Если получено сообщение ModuleNotFoundError, проверьте активное виртуальное окружение и выбранный интерпретатор. Убедитесь, что httpx добавлена в requirements.txt, чтобы зависимость проекта была явно указана.

## 5. Первый запрос

Создайте в корне проекта файл http_first_request.py:

~~~python
import httpx

url = "https://example.com/"

response = httpx.get(url, timeout=10.0)

print("Статус:", response.status_code)
print("Тип содержимого:", response.headers.get("content-type"))
print("Первые 300 символов:")
print(response.text[:300])
~~~

Запустите:

~~~powershell
python http_first_request.py
~~~

Разбор кода:

**import httpx** — оператор import подключает библиотеку. Без импорта имя httpx недоступно в текущем файле.

**url = "https://example.com/"** — оператор присваивания = сохраняет адрес в переменной url. Переменная удобна тем, что адрес можно заменить в одном месте. example.com — демонстрационный домен; доступность может зависеть от сети, прокси или корпоративных ограничений.

**response = httpx.get(url, timeout=10.0)** — вызываем функцию get, которая отправляет GET-запрос. Именованный аргумент timeout задаёт ограничение времени ожидания. Число 10.0 — значение с плавающей точкой. Не следует понимать его как обещание, что абсолютно весь сценарий завершится ровно за десять секунд: тайм-аут применяется к сетевым этапам.

Результат сохраняется в response — объект ответа.

**response.status_code** — атрибут с числовым HTTP-статусом.

**response.headers.get("content-type")** — обращение к заголовкам ответа. Метод get получает значение по ключу. Если ключ отсутствует, он возвращает None, а не вызывает KeyError. Заголовок content-type сообщает тип содержимого, например text/html.

**response.text[:300]** — текст ответа и операция среза. Срез [:300] означает взять символы от начала строки до позиции 300, не включая позицию 300. Это позволяет не выводить в терминал целую большую страницу.

## 6. Проверка HTTP-статуса

Вызов httpx.get() может вернуть ответ со статусом 404. Сам факт получения ответа не означает, что ресурс найден. Чтобы считать ошибочные HTTP-статусы исключениями, вызовите метод raise_for_status():

~~~python
response.raise_for_status()
~~~

Это новый для нашего примера метод. Он проверяет статус и при клиентской или серверной HTTP-ошибке возбуждает исключение httpx.HTTPStatusError. Преимущество — код не продолжит обрабатывать страницу ошибки так, будто это ожидаемое содержимое.

Не каждый статус, отличный от 200, обязательно нужно обрабатывать одинаково: например, перенаправления имеют собственный смысл. Но для простого учебного загрузчика raise_for_status() — понятный способ обнаружить HTTP-ошибку.

## 7. Обработка ошибок через try и except

Если исключение не обработано, программа может завершиться с трассировкой — диагностическим выводом, показывающим место ошибки и последовательность вызовов. Для контролируемой обработки используем try и except:

~~~python
import httpx

try:
    response = httpx.get("https://example.com/", timeout=10.0)
    response.raise_for_status()
    print("Страница успешно получена")
except httpx.HTTPStatusError as error:
    print("Сервер вернул ошибочный HTTP-статус:", error)
except httpx.RequestError as error:
    print("Не удалось выполнить сетевой запрос:", error)
~~~

**try** начинает блок, в котором могут возникнуть исключения. Мы помещаем туда запрос и проверку статуса.

**except** задаёт действия при исключении определённого типа.

**as error** связывает пойманное исключение с переменной error. Так можно прочитать диагностическое сообщение. Имя error — обычное имя переменной; можно использовать другое понятное название.

**httpx.HTTPStatusError** относится к ошибочному HTTP-статусу после вызова raise_for_status(). **httpx.RequestError** — базовый тип для ошибок выполнения запроса, например проблем соединения и тайм-аутов.

Порядок обработчиков важен: сначала ставьте более конкретный тип исключения, затем более общий. Иначе общий обработчик может перехватить ошибку раньше конкретного.

Преимущество try/except — программа может объяснить причину сбоя и выполнить предусмотренную реакцию. Это не устраняет саму сетевую проблему, а делает её обработку контролируемой. Не используйте пустой except: без разбора: так можно скрыть ошибки в собственном коде.

## 8. Зачем нужен тайм-аут

Если сервер перестал отвечать, программа без ограничения ожидания может надолго задержаться. Для приложения, где языковая модель вызывает инструмент, это особенно плохо: пользователь ждёт результат, а весь диалог тормозится.

Пример:

~~~python
response = httpx.get(url, timeout=10.0)
~~~

Тайм-аут ограничивает ожидание сетевых этапов. Значение следует выбирать по назначению инструмента. Не стоит бездумно увеличивать его: более долгое ожидание не гарантирует, что сервер ответит. Позже мы также ограничим объём загружаемых данных, количество результатов и перенаправления.

## 9. Функция загрузки текста страницы

Создайте файл http_fetch_demo.py:

~~~python
import httpx


def fetch_page_text(url: str) -> str:
    """Загрузить страницу и вернуть текст её содержимого."""
    try:
        response = httpx.get(url, timeout=10.0)
        response.raise_for_status()
        return response.text
    except httpx.HTTPStatusError as error:
        return f"Ошибка HTTP: {error.response.status_code}"
    except httpx.RequestError as error:
        return f"Сетевая ошибка: {error}"


page_text = fetch_page_text("https://example.com/")
print(page_text[:500])
~~~

Разбор:

**def** — ключевое слово для определения функции. fetch_page_text — имя функции. Параметр url получает адрес.

**url: str** — аннотация типа, которая документирует ожидание строки. **-> str** — аннотация возвращаемого значения. Аннотации помогают читателю и редактору, но сами по себе не заставляют Python автоматически проверять тип каждого аргумента.

**docstring** — строка документации внутри функции. Она кратко объясняет назначение кода.

**return** завершает функцию и передаёт значение вызвавшему коду. Это отличается от print: print показывает данные в терминале, а return возвращает их для дальнейшего использования.

**f-строка** — форматированная строка, начинающаяся с буквы f. В выражении f"Ошибка HTTP: {error.response.status_code}" значение в фигурных скобках подставляется в строку. Если статус равен 404, получится «Ошибка HTTP: 404». Это удобнее ручного склеивания строк.

В этой учебной функции и успешный результат, и ошибка возвращаются строками. Это просто для первого примера, но не идеально для большой программы: вызывающему коду трудно надёжно отличить содержимое страницы от сообщения об ошибке. Поэтому дальше рассмотрим структурированный результат.

## 10. Структурированный результат в виде словаря

~~~python
import httpx


def fetch_page(url: str) -> dict:
    try:
        response = httpx.get(url, timeout=10.0)
        response.raise_for_status()
        return {
            "ok": True,
            "status_code": response.status_code,
            "text": response.text,
            "error": None,
        }
    except httpx.HTTPStatusError as error:
        return {
            "ok": False,
            "status_code": error.response.status_code,
            "text": "",
            "error": "Сервер вернул ошибочный HTTP-статус",
        }
    except httpx.RequestError:
        return {
            "ok": False,
            "status_code": None,
            "text": "",
            "error": "Не удалось выполнить сетевой запрос",
        }


result = fetch_page("https://example.com/")
if result["ok"]:
    print(result["text"][:300])
else:
    print(result["error"])
~~~

Функция возвращает словарь с одинаковыми ключами в обоих случаях.

- ok — булево значение; True означает успех, False — неудачу.
- status_code — код ответа или None, если ответ с кодом не был получен.
- text — текст страницы либо пустая строка при ошибке.
- error — сообщение об ошибке или None при успехе.

None — специальное значение Python, обозначающее отсутствие значения. Оно позволяет отличить неизвестный статус от числового кода.

Условие if result["ok"] проверяет значение по ключу ok. Если оно истинно, выводим текст; иначе выполняется ветка else. Структурированный результат удобнее одной строки: вызывающий код проверяет поле ok, а не пытается угадать успех по формулировке сообщения.

Словарь тоже требует соглашения о названиях ключей и типах значений. В больших проектах можно применять специальные классы, но на текущем этапе словарь хорошо показывает идею структуры данных.

## 11. Частые ошибки

**ModuleNotFoundError: No module named 'httpx'.** Библиотека не установлена в используемом окружении. Выполните python -m pip install httpx и проверьте выбранный интерпретатор.

**Тайм-аут.** Сервер долго не отвечает, соединение нестабильно или сеть ограничивает доступ. Проверьте адрес и соединение, а также не забывайте, что сетевые службы могут быть временно недоступны.

**Ошибка DNS.** DNS (Domain Name System — система доменных имён) преобразует имя сайта в сетевой адрес. Если имя не разрешается, соединение не установится.

**404.** Сервер доступен, но ресурс по указанному пути не найден. Проверьте URL.

**403.** Сервер отказал в доступе. Не пытайтесь обходить ограничения; используйте разрешённый источник или официальный API.

**Ошибка SSL/TLS.** TLS — технология защиты сетевого соединения. Ошибки сертификата могут быть связаны с системным временем, сертификатами или корпоративной сетью. Не устраняйте их отключением проверки сертификата: это ослабляет безопасность и позволяет легче подменить сервер.

**HTML вместо JSON.** Это может быть совершенно нормальным результатом: формат зависит от запрошенного ресурса. Не следует считать, что любой ответ сервера — JSON.

Сегодня мы научились отправлять HTTP-запросы, читать статус и содержимое ответа, задавать тайм-аут, различать сетевые ошибки и HTTP-статусы, а также обрабатывать исключения. Мы написали функцию загрузки страницы и увидели, почему структурированный результат удобнее произвольной строки.

Главные правила:
1. Используйте httpx вместо самостоятельной реализации HTTP-клиента.
2. Проверяйте статус ответа.
3. Всегда задавайте разумный тайм-аут.
4. Обрабатывайте конкретные ожидаемые типы исключений.
5. Разделяйте возвращаемые данные и диагностический вывод.
6. Помните, что будущий web_fetch должен проверять URL и ограничивать получаемые данные.
