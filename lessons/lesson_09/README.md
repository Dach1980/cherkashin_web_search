# Урок № 9. Создаём инструмент web_fetch: загрузка веб-страницы и извлечение текста

## 1. Цель урока

В уроке № 8 мы создали учебный прототип `web_search`: он отправляет поисковый запрос и возвращает список результатов с заголовками, ссылками и фрагментами текста. Но поисковый результат — это ещё не сама статья. Обычно поисковая система показывает лишь короткое описание, а для полноценного ответа нужно открыть найденную страницу и прочитать её содержимое.

В этом уроке создадим второй самостоятельный инструмент — `web_fetch`. Он будет принимать URL, проверять базовую корректность адреса, загружать страницу через `httpx` с тайм-аутом, проверять HTTP-статус и тип содержимого, разбирать HTML через `BeautifulSoup`, удалять типовые служебные элементы, извлекать заголовок и текст и ограничивать длину результата.

Это пока обычная Python-функция, а не готовый MCP-инструмент. На следующих этапах мы подключим её к MCP-серверу и добавим дополнительные ограничения безопасности. В частности, проверка URL в этом уроке не является полноценной защитой от SSRF и доступа к внутренним сетевым адресам.

## 2. Термины урока

**Fetch** — получение содержимого ресурса по адресу. В нашем проекте `web_fetch` получает страницу по URL и возвращает её текст в удобном для дальнейшей обработки виде.

**HTML (HyperText Markup Language — язык гипертекстовой разметки)** — формат разметки веб-страниц. Он описывает заголовки, абзацы, ссылки, списки, таблицы и другие элементы. HTML — не то же самое, что обычный текст: вместе с текстом в нём присутствуют теги и атрибуты.

**Тег (tag)** — элемент разметки, например `<p>` для абзаца или `<h1>` для заголовка первого уровня. **Атрибут (attribute)** — дополнительное свойство тега, например `href` у ссылки.

**Парсер (parser)** — программа, которая разбирает исходные данные по правилам формата и создаёт удобную структуру. `BeautifulSoup` — библиотека Python для разбора HTML и XML.

**Извлечение текста (text extraction)** — получение читаемого текста из исходной страницы без HTML-разметки и типовых служебных блоков.

**DOM (Document Object Model — объектная модель документа)** — представление HTML-страницы в виде дерева элементов. Парсер позволяет находить узлы этого дерева и извлекать из них содержимое.

**CSS-селектор (CSS selector)** — выражение для выбора элементов по тегу, классу или другим признакам. Например, `script` выбирает все теги сценариев, а `.advertisement` — элементы с классом `advertisement`.

**Content-Type** — HTTP-заголовок, который сообщает тип содержимого ответа, например `text/html`. Мы проверим его, чтобы не пытаться обрабатывать PDF, изображение или JSON как обычную HTML-страницу.

**Очистка данных (cleaning)** — удаление или нормализация ненужных частей. В нашем случае уберём скрипты, стили, навигацию и некоторые служебные блоки. Это эвристика: у разных сайтов структура отличается, поэтому нельзя гарантировать, что будет извлечён только основной текст статьи.

**Ограничение длины (length limit)** — максимальное количество символов, которое функция отдаёт вызывающему коду. Оно не даёт одной большой странице бесконтрольно разрастись в контексте языковой модели. В этом уроке ограничиваем длину итогового текста; в дальнейшем отдельно ограничим размер сетевого ответа.

**SSRF (Server-Side Request Forgery — подделка серверного запроса)** — класс уязвимостей, при котором приложение под влиянием переданного URL делает запросы к адресам, к которым пользователь не должен обращаться, например к внутренним сервисам. Нельзя считать произвольный URL безопасным только потому, что он начинается с HTTPS.

## 3. Как будет работать web_fetch

1. Получаем строку URL.
2. Проверяем тип строки, схему http/https и наличие имени узла.
3. Отправляем GET-запрос с тайм-аутом.
4. Проверяем статус ответа.
5. Проверяем заголовок Content-Type.
6. Передаём HTML в BeautifulSoup.
7. Удаляем очевидные служебные элементы.
8. Получаем заголовок страницы и текст.
9. Ограничиваем длину текста.
10. Возвращаем словарь с одинаковым набором ключей при успехе и ошибке.

Почему не возвращать только строку? Потому что вызывающей программе нужно понять, что произошло. Пустая строка может означать пустую статью, а может — неудачную загрузку. Структурированный результат позволяет отдельно передать флаг успеха, статус, заголовок, текст и описание ошибки.

## 6. Первый разбор HTML через BeautifulSoup

Создайте файл parse_html_demo.py:

~~~python
from bs4 import BeautifulSoup

html = """
<html>
<head><title>Тестовая страница</title></head>
<body>
    <h1>Главный заголовок</h1>
    <p>Первый абзац.</p>
    <p>Второй абзац.</p>
</body>
</html>
"""

soup = BeautifulSoup(html, "html.parser")

print("Заголовок страницы:", soup.title.get_text(strip=True))
print("Главный заголовок:", soup.find("h1").get_text(strip=True))

for paragraph in soup.find_all("p"):
    print(paragraph.get_text(strip=True))
~~~

Запустите:

~~~powershell
python parse_html_demo.py
~~~

Ожидаемый вывод:

~~~text
Заголовок страницы: Тестовая страница
Главный заголовок: Главный заголовок
Первый абзац.
Второй абзац.
~~~

Разберём новые конструкции.

**from bs4 import BeautifulSoup** — форма импорта, которая загружает конкретное имя из модуля. В отличие от import bs4, после такого импорта можно обращаться к классу напрямую как BeautifulSoup.

**BeautifulSoup(html, "html.parser")** — создаёт объект-разборщик. Первый аргумент — HTML, второй — выбранный парсер. html.parser встроен в стандартную библиотеку Python, поэтому для этого режима не требуется отдельный парсерный пакет.

**soup.title** — находит элемент title. Это краткая форма доступа к тегу, но она может вернуть None, если элемента нет. В надёжном коде отсутствие элемента обязательно нужно учитывать.

**get_text(strip=True)** — извлекает текст без HTML-тегов и обрезает пробельные символы по краям фрагментов. Аргумент strip=True — именованный аргумент метода.

**soup.find("h1")** — возвращает первый найденный элемент h1 или None, если совпадений нет.

**soup.find_all("p")** — возвращает коллекцию всех найденных абзацев.

**for paragraph in ...** — цикл перебирает найденные элементы по одному. На каждой итерации переменная paragraph ссылается на очередной элемент.

Преимущество парсера перед ручным удалением тегов с помощью строковых замен в том, что HTML — вложенный формат. Простая замена текста не справится с разными атрибутами, вложенными элементами и пробелами. Парсер понимает структуру документа и предоставляет методы поиска.

## 7. Удаляем служебные элементы

~~~python
from bs4 import BeautifulSoup

html = """
<html>
<head>
    <title>Статья</title>
    <style>body { color: black; }</style>
</head>
<body>
    <nav>Главная | Каталог</nav>
    <main>
        <h1>Полезный материал</h1>
        <p>Основной текст статьи.</p>
    </main>
    <script>console.log("служебный код");</script>
    <footer>Подвал сайта</footer>
</body>
</html>
"""

soup = BeautifulSoup(html, "html.parser")

for element in soup(["script", "style", "nav", "footer"]):
    element.decompose()

print(soup.get_text(" ", strip=True))
~~~

Метод decompose() удаляет элемент вместе с его содержимым из разобранного дерева. Мы выбираем теги script, style, nav и footer, а затем удаляем каждый найденный элемент.

Выражение soup([...]) — поддерживаемый BeautifulSoup способ найти теги по списку имён. Внутри списка строки обозначают имена HTML-тегов.

Аргумент " " в get_text(" ", strip=True) задаёт разделитель между кусками текста. Благодаря пробелу соседние текстовые узлы не слипаются в одно слово.

Почему удаляем не всё подряд? Потому что задача — убрать типовые помехи, не потеряв полезное содержимое. Однако на одном сайте меню может находиться в div с классом, а на другом основной текст может быть обёрнут в нестандартный элемент. Универсального правила для всех сайтов нет.

Важно: названия и структура элементов зависят от сайта. На некоторых страницах меню и основная статья используют одинаковые теги или классы. Поэтому извлечение текста — практическая эвристика, а не идеальное восстановление смысла страницы.

## 8. Реализуем функцию web_fetch

Создайте файл src/web_search_mcp/web_fetch.py. Если каталог src/web_search_mcp уже существует, добавьте в него новый файл. Полный код:

~~~python
from urllib.parse import urlsplit

import httpx
from bs4 import BeautifulSoup


DEFAULT_TIMEOUT_SECONDS = 15.0
DEFAULT_MAX_PAGE_CHARS = 12_000

USER_AGENT = (
    "Mozilla/5.0 (compatible; LocalWebFetch/1.0; "
    "+https://example.com/bot-info)"
)


def _error_result(
    url: str,
    error: str,
    status_code: int | None = None,
) -> dict:
    """Создать результат ошибки с единым набором полей."""
    return {
        "ok": False,
        "url": url,
        "status_code": status_code,
        "title": "",
        "text": "",
        "truncated": False,
        "error": error,
    }


def _extract_page(html: str, max_chars: int) -> tuple[str, str, bool]:
    """Извлечь заголовок и текст из HTML, ограничив длину текста."""
    soup = BeautifulSoup(html, "html.parser")

    title = ""
    if soup.title is not None:
        title = soup.title.get_text(" ", strip=True)

    for element in soup(
        ["script", "style", "nav", "footer", "header", "noscript", "svg"]
    ):
        element.decompose()

    main = soup.find("main") or soup.find("article") or soup.body or soup
    text = main.get_text(" ", strip=True)
    text = " ".join(text.split())

    truncated = len(text) > max_chars
    if truncated:
        text = text[:max_chars]

    return title, text, truncated


def web_fetch(
    url: str,
    max_chars: int = DEFAULT_MAX_PAGE_CHARS,
    timeout: float = DEFAULT_TIMEOUT_SECONDS,
) -> dict:
    """Загрузить веб-страницу и вернуть её заголовок и очищенный текст."""
    if not isinstance(url, str):
        return _error_result("", "URL должен быть строкой.")

    url = url.strip()
    if not url:
        return _error_result(url, "URL не должен быть пустым.")

    if not isinstance(max_chars, int) or isinstance(max_chars, bool):
        return _error_result(url, "max_chars должен быть целым числом.")
    if max_chars < 1:
        return _error_result(url, "max_chars должен быть больше нуля.")

    if not isinstance(timeout, (int, float)) or isinstance(timeout, bool):
        return _error_result(url, "timeout должен быть числом.")
    if timeout <= 0:
        return _error_result(url, "timeout должен быть больше нуля.")

    parts = urlsplit(url)
    if parts.scheme not in ("http", "https") or not parts.hostname:
        return _error_result(
            url,
            "Разрешены только абсолютные URL со схемой http или https.",
        )

    try:
        response = httpx.get(
            url,
            timeout=float(timeout),
            follow_redirects=True,
            headers={"User-Agent": USER_AGENT},
        )
        response.raise_for_status()

    except httpx.HTTPStatusError as error:
        return _error_result(
            url,
            f"Сервер вернул HTTP-ошибку: {error.response.status_code}.",
            status_code=error.response.status_code,
        )
    except httpx.RequestError as error:
        return _error_result(url, f"Не удалось загрузить страницу: {error}")

    content_type = response.headers.get("content-type", "").lower()
    if "text/html" not in content_type and "application/xhtml+xml" not in content_type:
        return _error_result(
            url,
            f"Ожидалась HTML-страница, получен Content-Type: {content_type or 'не указан'}.",
            status_code=response.status_code,
        )

    title, text, truncated = _extract_page(response.text, max_chars)

    if not text:
        return _error_result(
            url,
            "HTML получен, но читаемый текст не найден.",
            status_code=response.status_code,
        )

    return {
        "ok": True,
        "url": str(response.url),
        "status_code": response.status_code,
        "title": title,
        "text": text,
        "truncated": truncated,
        "error": None,
    }


if __name__ == "__main__":
    result = web_fetch("https://example.com/")

    if result["ok"]:
        print("Заголовок:", result["title"])
        print("HTTP-статус:", result["status_code"])
        print("Текст:")
        print(result["text"])
        print("Текст обрезан:", result["truncated"])
    else:
        print("Ошибка:", result["error"])
~~~

### Важное замечание о безопасности

Этот код — учебный первый вариант. Проверка схемы URL защищает от некоторых некорректных входных значений, но **не является достаточной защитой для публичного сервиса**. Перед использованием с недоверенными URL нужно дополнительно проверять IP-адреса, блокировать loopback/private/link-local и другие запрещённые диапазоны, безопасно контролировать перенаправления и учитывать DNS rebinding. Это будет отдельной задачей в уроке о безопасности. Не выставляйте учебную функцию как неограниченный сетевой сервис.

## 9. Подробный разбор кода web_fetch

### 9.1. Импорты

~~~python
from urllib.parse import urlsplit

import httpx
from bs4 import BeautifulSoup
~~~

urllib.parse — модуль стандартной библиотеки Python для разбора и сборки URL. urlsplit разбивает URL на части: схему, сетевой адрес, путь, параметры и фрагмент.

Мы не пишем собственный разбор адреса вручную. URL может содержать порт, путь, параметры и другие части; специализированная функция уменьшает риск ошибиться.

httpx отправляет HTTP-запросы. BeautifulSoup разбирает HTML и позволяет находить элементы и получать текст.

### 9.2. Константы

~~~python
DEFAULT_TIMEOUT_SECONDS = 15.0
DEFAULT_MAX_PAGE_CHARS = 12_000
~~~

Константа — имя, которое по соглашению программы не предполагается менять в обычной работе. В Python нет отдельного синтаксиса, который делает такие имена неизменяемыми; верхний регистр — общепринятая договорённость.

12_000 — целое число 12000. Символ подчёркивания в числовом литерале улучшает читаемость и не меняет значение. 15.0 — число с плавающей точкой.

Почему значения находятся в одном месте? Чтобы не разносить «магические числа» по коду. Если позже потребуется изменить стандартный тайм-аут, это можно сделать одной правкой.

### 9.3. Функция _error_result

~~~python
def _error_result(
    url: str,
    error: str,
    status_code: int | None = None,
) -> dict:
    return {
        "ok": False,
        "url": url,
        "status_code": status_code,
        "title": "",
        "text": "",
        "truncated": False,
        "error": error,
    }
~~~

Имя начинается с одного символа подчёркивания: _error_result. Это соглашение означает, что функция предназначена для внутреннего использования в модуле. Сам Python не запрещает импортировать её извне.

status_code: int | None = None демонстрирует аннотацию объединённого типа. Символ | в аннотации означает, что значение может быть целым числом или None. Такая запись поддерживается в Python 3.10 и новее.

= None задаёт значение по умолчанию. Если вызывающий код не передаст статус, поле будет содержать None.

Словарь всегда имеет одинаковые ключи. Это уменьшает количество специальных случаев в вызывающем коде: не нужно каждый раз проверять, существует ли ключ title или text.

### 9.4. Функция _extract_page

~~~python
def _extract_page(html: str, max_chars: int) -> tuple[str, str, bool]:
~~~

Эта функция отделяет разбор HTML от сетевого запроса. Такое разделение называется **разделением ответственности**: одна функция загружает страницу, другая извлекает данные. Это облегчает тестирование и позволяет проверять HTML без доступа к интернету.

Аннотация tuple[str, str, bool] означает кортеж из трёх значений: строка заголовка, строка текста и булево значение. **Кортеж (tuple)** — упорядоченная последовательность значений, которую обычно используют для возврата нескольких связанных результатов.

~~~python
soup = BeautifulSoup(html, "html.parser")

title = ""
if soup.title is not None:
    title = soup.title.get_text(" ", strip=True)
~~~

Сначала задаём пустую строку. Затем проверяем, существует ли заголовок. Оператор is not None проверяет, что объект не является специальным значением None. Для такой проверки это понятнее и надёжнее, чем сравнивать результат с пустой строкой.

Если элемента title нет, значение остаётся пустой строкой. Благодаря проверке мы не вызываем get_text() у отсутствующего элемента и избегаем ошибки AttributeError.

~~~python
for element in soup(
    ["script", "style", "nav", "footer", "header", "noscript", "svg"]
):
    element.decompose()
~~~

Цикл for проходит по найденным тегам. Для каждого элемента вызывается decompose(), который удаляет его вместе с содержимым.

Обратите внимание: мы не удаляем все элементы div или section. Они могут содержать саму статью. Слишком агрессивная очистка рискует удалить полезный текст.

~~~python
main = soup.find("main") or soup.find("article") or soup.body or soup
~~~

Здесь применяется оператор or не только для логики, но и для выбора первого подходящего объекта. В Python оператор or возвращает один из своих операндов: сначала проверяет первый; если он истинный, возвращает его, иначе проверяет следующий.

В результате выбирается первый доступный контейнер по приоритету:
1. main — основной контент страницы;
2. article — самостоятельная статья;
3. body — тело документа;
4. весь разобранный документ soup.

Это компактнее длинной цепочки if/elif. Но есть нюанс: Python считает пустые коллекции и некоторые объекты ложными. В данном коде это обычно приемлемо, но при сложной логике предпочтительнее явные проверки is not None.

~~~python
text = main.get_text(" ", strip=True)
text = " ".join(text.split())
~~~

Первая строка извлекает текст с пробелами между фрагментами. Вторая нормализует пробелы.

Метод split() без аргумента разбивает строку по последовательностям пробельных символов и удаляет лишние пустые части. Метод " ".join(...) объединяет полученные слова одним обычным пробелом. Например, несколько переносов строк и табуляций превращаются в один пробел.

~~~python
truncated = len(text) > max_chars
if truncated:
    text = text[:max_chars]
~~~

len(text) возвращает количество символов в строке. Сравнение > проверяет, длиннее ли текст установленного лимита.

Переменная truncated показывает, пришлось ли обрезать текст. Если значение True, вызывающий код знает, что получил не всё содержимое.

Срез text[:max_chars] возвращает строку от начала до указанной позиции, не включая позицию max_chars. Например, "abcdef"[:3] даст "abc".

В конце функция возвращает три значения:

~~~python
return title, text, truncated
~~~

При таком возврате Python формирует кортеж. В вызывающем коде три части можно сразу присвоить трём переменным.

### 9.5. Проверка входных параметров

~~~python
if not isinstance(url, str):
    return _error_result("", "URL должен быть строкой.")
~~~

isinstance(value, type) проверяет, является ли значение экземпляром указанного типа. Здесь мы не пытаемся вызывать строковые методы у значения, которое может оказаться числом или другим объектом.

~~~python
url = url.strip()
if not url:
    return _error_result(url, "URL не должен быть пустым.")
~~~

Метод strip() удаляет пробельные символы по краям строки. Условие if not url проверяет пустую строку. В Python пустая строка считается ложным значением.

~~~python
if not isinstance(max_chars, int) or isinstance(max_chars, bool):
~~~

Почему есть вторая проверка? Потому что в Python тип bool является подклассом int: isinstance(True, int) возвращает True. Но использовать True как лимит длины — ошибка смысла. Поэтому булево значение исключается отдельно.

Оператор or здесь означает «или»: если лимит не целое число или оказался булевым значением, параметр отклоняется.

Похожим образом проверяем timeout. Важно отклонять нулевой и отрицательный тайм-аут: такие значения не подходят для нормальной загрузки.

### 9.6. Разбор URL

~~~python
parts = urlsplit(url)
if parts.scheme not in ("http", "https") or not parts.hostname:
    return _error_result(
        url,
        "Разрешены только абсолютные URL со схемой http или https.",
    )
~~~

urlsplit(url) разбивает адрес на компоненты. parts.scheme содержит схему, например https. parts.hostname содержит имя узла, например example.com.

Оператор not in проверяет, что значение отсутствует в последовательности. Условие отклоняет адреса со схемой, отличной от http или https. Вторая часть отклоняет URL без имени узла.

Скобки вокруг ("http", "https") создают кортеж из двух допустимых значений. Кортеж подходит для небольшого фиксированного набора вариантов.

Это только базовая проверка корректности. Она не подтверждает, что домен безопасен, что IP-адрес публичный или что перенаправление не приведёт к внутреннему адресу. Полную сетевую защиту разберём отдельно.

### 9.7. HTTP-запрос и обработка ошибок

~~~python
response = httpx.get(
    url,
    timeout=float(timeout),
    follow_redirects=True,
    headers={"User-Agent": USER_AGENT},
)
response.raise_for_status()
~~~

httpx.get отправляет GET-запрос. Аргумент timeout задаёт тайм-аут. float(timeout) приводит значение к числу с плавающей точкой.

follow_redirects=True разрешает автоматически следовать перенаправлениям. Перенаправление — ответ сервера, указывающий на другой адрес. В реальном безопасном инструменте недостаточно просто включить перенаправления: нужно контролировать каждый следующий адрес. Здесь этот параметр демонстрирует обычное поведение клиента, а безопасность перенаправлений будет отдельным этапом.

headers={...} передаёт HTTP-заголовки. User-Agent сообщает серверу, какой клиент делает запрос. Уважайте условия сайта и не маскируйте автоматизированный доступ для обхода ограничений. Значение в примере демонстрационное; при публикации проекта замените его на честную идентификацию приложения и контактную страницу, если они есть.

raise_for_status() возбуждает исключение для ошибочного HTTP-статуса. Поэтому код переходит к обработчикам except, если сервер вернул, например, 404 или 500.

~~~python
except httpx.HTTPStatusError as error:
    return _error_result(
        url,
        f"Сервер вернул HTTP-ошибку: {error.response.status_code}.",
        status_code=error.response.status_code,
    )
except httpx.RequestError as error:
    return _error_result(url, f"Не удалось загрузить страницу: {error}")
~~~

Первый обработчик отвечает за ответ с неуспешным HTTP-статусом. Второй — за ошибки запроса, например сетевую проблему или тайм-аут. Обработчики стоят в правильном порядке: конкретный тип ошибки идёт перед другим типом.

Фрагмент f-строки с выражением в фигурных скобках вычисляется и вставляется в текст сообщения.

### 9.8. Проверка Content-Type

~~~python
content_type = response.headers.get("content-type", "").lower()
~~~

response.headers содержит заголовки ответа. Метод get("content-type", "") возвращает значение заголовка, а если его нет — пустую строку. Метод lower() приводит буквы к нижнему регистру, чтобы сравнение не зависело от регистра.

~~~python
if "text/html" not in content_type and "application/xhtml+xml" not in content_type:
~~~

Оператор and требует, чтобы обе части условия были истинными. То есть мы отклоняем ответ, если в типе содержимого нет ни text/html, ни application/xhtml+xml.

Почему это важно? Если сервер вернул PDF или изображение, разбирать байты как обычную HTML-страницу неправильно. Позднее при необходимости можно сделать отдельные инструменты для PDF и других форматов.

### 9.9. Формирование успешного результата

~~~python
return {
    "ok": True,
    "url": str(response.url),
    "status_code": response.status_code,
    "title": title,
    "text": text,
    "truncated": truncated,
    "error": None,
}
~~~

ok — признак успеха. url содержит конечный адрес после перенаправления, который сообщает объект ответа. status_code хранит HTTP-статус. title и text — извлечённые данные. truncated показывает, был ли текст обрезан. error: None означает, что ошибки не зарегистрировано.

Словарь результата — договор между функцией и её будущими потребителями. Позже MCP-сервер сможет передать эти данные модели как результат инструмента.

### 9.10. Точка входа для запуска файла

~~~python
if __name__ == "__main__":
    result = web_fetch("https://example.com/")
~~~

Переменная __name__ — специальная переменная Python. Когда файл запускают напрямую, её значение равно "__main__". Когда модуль импортируют из другого файла, значение обычно становится именем модуля.

Поэтому блок позволяет использовать один файл в двух режимах:
- запустить его как учебную программу для ручной проверки;
- импортировать функцию web_fetch из другого модуля, не выполняя демонстрационный запрос автоматически.

Это распространённый шаблон Python. Он особенно полезен в проекте, где функцию позже будет импортировать MCP-сервер.

## 11. Как web_search и web_fetch работают вместе

В нашем проекте это два разных инструмента:

- `web_search(query)` — ищет страницы и возвращает список найденных ссылок с краткими описаниями;
- `web_fetch(url)` — получает одну конкретную страницу по URL и извлекает из неё текст.

Типовой сценарий:

1. Пользователь задаёт вопрос.
2. Модель вызывает web_search с поисковой фразой.
3. Инструмент возвращает несколько результатов.
4. Модель выбирает подходящую ссылку.
5. Модель вызывает web_fetch для этой ссылки.
6. Инструмент возвращает заголовок и текст страницы.
7. Модель формирует ответ, опираясь на полученные данные.

Поисковая выдача и содержимое страницы имеют разную роль. Не стоит передавать модели весь HTML: там много навигации, сценариев и служебной разметки. Извлечённый текст компактнее и удобнее для анализа.

При этом извлечение текста не доказывает достоверность содержимого. Страница может быть устаревшей, рекламной или ошибочной. Модель должна учитывать источник и контекст, а приложение — по возможности сохранять URL, чтобы пользователь мог проверить первоисточник.

## 12. Частые ошибки

**ModuleNotFoundError: No module named 'web_search_mcp'.** Python не видит пакет. Проверьте, что вы находитесь в корне проекта, активировали правильное виртуальное окружение и настроили путь импорта для src-структуры.

**ModuleNotFoundError: No module named 'bs4'.** Установите пакет beautifulsoup4 в то же окружение, из которого запускаете код.

**AttributeError при обращении к soup.title.** На некоторых HTML-страницах заголовок отсутствует. Проверяйте, что элемент не равен None, прежде чем вызывать его методы.

**Сайт вернул 403 или 429.** Доступ запрещён либо действует ограничение частоты запросов. Не пытайтесь обходить запрет, CAPTCHA или лимиты. Используйте разрешённый источник, соблюдайте правила сайта и делайте запросы реже.

**Получен Content-Type, не похожий на HTML.** Возможно, ссылка ведёт на PDF, изображение, JSON или файл. Текущий web_fetch предназначен для HTML, поэтому такой ответ отклоняется.

**Текст пустой или содержит меню вместо статьи.** Сайт может строить содержимое нестандартно или отдавать страницу, где основной текст загружается JavaScript-кодом. BeautifulSoup разбирает полученный HTML, но сам по себе не запускает JavaScript. Для некоторых сайтов потребуются другие методы получения содержимого.

**Извлечённый текст обрезан.** Это ожидаемое поведение, когда длина превышает max_chars. Проверьте поле truncated. Не убирайте ограничение без оценки последствий для памяти, времени обработки и контекста модели.

**Страница долго загружается.** Проверьте соединение и тайм-аут. Не делайте тайм-аут бесконечным: инструмент должен возвращать управление даже при недоступности источника.
