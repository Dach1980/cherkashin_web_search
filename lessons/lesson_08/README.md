## 1. Цель урока

## 2. Термины и понятия

**Web Search** — «поиск в интернете». В нашем проекте это функция, которая отправляет поисковую фразу внешней поисковой системе и возвращает структурированный список найденных страниц.

**Поисковая система (search engine)** — сервис, который помогает находить веб-страницы по запросу. Он обычно поддерживает собственный индекс страниц, ранжирует результаты и показывает выдачу. Примеры известных поисковых систем — Google, Bing и DuckDuckGo.

**Поисковый провайдер (search provider)** — внешний сервис, к которому обращается наша программа за результатами поиска. В этом уроке для учебного примера используем HTML-страницу выдачи DuckDuckGo. Отдельного API-ключа для такого учебного запроса обычно не требуется, но это не означает, что сервис гарантирует автоматизированный доступ, стабильную разметку или отсутствие ограничений.

**API (Application Programming Interface — программный интерфейс приложения)** — формализованный способ, с помощью которого одна программа взаимодействует с другой. Официальный поисковый API обычно возвращает структурированные данные, например JSON, и имеет документированные правила, лимиты и условия использования. HTML-страница выдачи — не то же самое, что официальный API.

**HTML (HyperText Markup Language — язык разметки гипертекста)** — формат разметки, который описывает структуру веб-страницы: заголовки, ссылки, абзацы и другие элементы. HTML не является обычным текстом: в нём есть теги и атрибуты.

**Парсинг (parsing)** — разбор данных по правилам формата. Мы будем разбирать HTML, чтобы найти нужные элементы, а не пытаться извлекать ссылки случайными операциями со строками.

**DOM (Document Object Model — объектная модель документа)** — представление HTML-документа в виде дерева элементов. Библиотека Beautiful Soup позволяет находить элементы этого дерева по тегам, классам и другим признакам.

**Селектор (selector)** — выражение, указывающее, какие элементы HTML нужно найти. Например, CSS-селектор .result выбирает элементы с классом result, а a обозначает ссылку.

**Сниппет (snippet)** — короткий фрагмент текста под названием результата. Он помогает понять, о чём страница, прежде чем открывать её.

**User-Agent** — заголовок HTTP-запроса, который сообщает серверу информацию о клиенте. В примере укажем описательный User-Agent. Это не способ обходить защиту и не гарантия, что сервис разрешит запросы.

**Лимит (limit)** — максимальное допустимое количество элементов или объём данных. Лимит результатов делает ответ предсказуемым и не позволяет вернуть слишком длинный список.

## 3. Как будет работать наш поиск

1. Пользователь или модель передаёт поисковую фразу, например «Python httpx документация».
2. Python проверяет, что запрос не пустой.
3. Программа отправляет HTTP GET-запрос к HTML-странице поисковой выдачи.
4. Сервер возвращает HTML.
5. Beautiful Soup разбирает HTML и помогает найти блоки результатов.
6. Из каждого блока извлекаются заголовок, URL и сниппет.
7. Программа оставляет не более заданного количества результатов.
8. Функция возвращает список словарей.

Важно: мы не создаём собственную поисковую систему. Мы пишем клиентский инструмент, который обращается к уже существующему поисковому сервису и преобразует его ответ в удобную для нашей программы структуру.

## 5. Сначала посмотрим на HTML

Поисковая страница содержит много разметки. Упрощённый пример одного результата может выглядеть так:

~~~html
<div class="result">
  <h2 class="result__title">
    <a href="https://docs.python.org/">Python documentation</a>
  </h2>
  <a class="result__snippet">Official documentation for Python.</a>
</div>
~~~

Это учебный фрагмент, показывающий принцип, а не обещание, что реальная поисковая страница всегда будет иметь именно такую структуру.

Разберём элементы:
- div — блочный HTML-элемент, который часто используют как контейнер;
- class="result" — атрибут класса, по которому можно найти контейнер;
- h2 — заголовок второго уровня;
- a — элемент ссылки;
- href — атрибут, в котором обычно хранится адрес ссылки;
- текст между открывающим и закрывающим тегом — видимое название ссылки.

Селектор .result означает «элемент с классом result». Селектор .result__title a означает «элемент a, находящийся внутри элемента с классом result__title».

Почему используем HTML-парсер, а не просто split()? Метод split() делит строку по заданному разделителю и не понимает структуру HTML. Разметка может содержать вложенные элементы, переносы строк, кавычки и дополнительные атрибуты. Парсер умеет работать с деревом элементов и делает извлечение устойчивее. При этом он не устраняет зависимость от структуры сайта: если провайдер изменит классы и формат HTML, селекторы может потребоваться обновить.

## 6. Создаём первую версию поиска

Создайте в корне проекта файл web_search_demo.py:

~~~python
import httpx
from bs4 import BeautifulSoup


SEARCH_URL = "https://html.duckduckgo.com/html/"
USER_AGENT = "PythonWebSearchLearningProject/1.0"


def web_search(query: str, max_results: int = 5) -> list[dict]:
    """Найти страницы и вернуть список названий, ссылок и сниппетов."""
    if not query.strip():
        return []

    params = {"q": query}
    headers = {"User-Agent": USER_AGENT}

    response = httpx.get(
        SEARCH_URL,
        params=params,
        headers=headers,
        timeout=10.0,
        follow_redirects=True,
    )
    response.raise_for_status()

    soup = BeautifulSoup(response.text, "html.parser")
    results = []

    for item in soup.select(".result"):
        title_link = item.select_one(".result__title a")
        snippet_element = item.select_one(".result__snippet")

        if title_link is None:
            continue

        title = title_link.get_text(" ", strip=True)
        url = title_link.get("href", "").strip()
        snippet = (
            snippet_element.get_text(" ", strip=True)
            if snippet_element is not None
            else ""
        )

        if not title or not url:
            continue

        results.append(
            {
                "title": title,
                "url": url,
                "snippet": snippet,
            }
        )

        if len(results) >= max_results:
            break

    return results


if __name__ == "__main__":
    search_query = input("Введите поисковый запрос: ")
    search_results = web_search(search_query)

    if not search_results:
        print("Результаты не найдены или поисковая страница не содержит ожидаемых блоков.")
    else:
        for number, result in enumerate(search_results, start=1):
            print(f"{number}. {result['title']}")
            print(f"   URL: {result['url']}")
            print(f"   Описание: {result['snippet']}")
            print()
~~~

Запустите:

~~~powershell
python web_search_demo.py
~~~

Введите, например, Python httpx documentation.

Если поисковый сервис доступен и не изменил разметку, программа выведет найденные заголовки, URL и краткие описания. Количество и содержание результатов зависят от поисковой системы, сети, региона и текущей доступности сервиса. Если сервис возвращает страницу проверки или защиты от автоматизированных запросов, учебный парсер может не получить результатов.

## 7. Подробный разбор кода

### 7.1. Импортируем библиотеки

~~~python
import httpx
from bs4 import BeautifulSoup
~~~

import httpx подключает библиотеку HTTP-клиента.

**from ... import ...** — конструкция импорта конкретного имени из модуля или пакета. Здесь мы импортируем BeautifulSoup из bs4. После этого можно писать BeautifulSoup(...), не указывая каждый раз bs4.BeautifulSoup(...).

Преимущество — код становится компактнее и показывает, какой именно инструмент используется. Не стоит импортировать всё подряд без необходимости: явные импорты упрощают чтение и поиск источника имён.

### 7.2. Константы

~~~python
SEARCH_URL = "https://html.duckduckgo.com/html/"
USER_AGENT = "PythonWebSearchLearningProject/1.0"
~~~

SEARCH_URL хранит адрес поисковой страницы, USER_AGENT — значение заголовка клиента.

Имена, записанные заглавными буквами с подчёркиваниями, — общепринятое соглашение Python для констант, то есть значений, которые по замыслу программы не должны меняться в ходе обычного выполнения. Python не запрещает изменить такую переменную; заглавное имя — договорённость для читателей кода.

Почему адрес и заголовок вынесены отдельно? Если понадобится изменить провайдера или User-Agent, настройка находится в одном месте, а не разбросана по функции.

### 7.3. Объявление функции и аннотации

~~~python
def web_search(query: str, max_results: int = 5) -> list[dict]:
~~~

- def объявляет функцию;
- web_search — имя функции;
- query: str — параметр query ожидается как строка;
- max_results: int = 5 — параметр количества результатов имеет значение по умолчанию 5;
- -> list[dict] — аннотация, документирующая, что функция возвращает список словарей.

**Значение по умолчанию** позволяет вызывать функцию просто как web_search("Python"), не указывая количество результатов каждый раз. При необходимости можно написать web_search("Python", max_results=3).

**Аннотация типа** помогает разработчику, редактору кода и средствам анализа понять ожидаемые данные. Она не является автоматической проверкой входных значений во время выполнения. Поэтому функцию всё равно нужно защищать проверками.

### 7.4. Проверяем пустой запрос

~~~python
if not query.strip():
    return []
~~~

Здесь используются сразу несколько конструкций.

**strip()** — строковый метод, который удаляет пробельные символы в начале и конце строки. Например, "  Python  ".strip() вернёт "Python".

**not** — логический оператор отрицания. Он меняет истинное значение на противоположное. Пустая строка считается ложным значением, поэтому not query.strip() истинно, если после удаления пробелов ничего не осталось.

**return []** завершает функцию и возвращает пустой список. Пустой список — корректный результат, когда искать нечего. Это лучше, чем отправлять бессмысленный запрос поисковому сервису.

Это одна из важных проверок входных данных: инструмент не должен выполнять ненужные сетевые операции, если пользователь передал пустую строку.

### 7.5. Параметры запроса и заголовки

~~~python
params = {"q": query}
headers = {"User-Agent": USER_AGENT}
~~~

params — словарь параметров запроса. В данном случае ключ q содержит поисковую фразу. httpx сам кодирует параметры URL, поэтому не нужно вручную склеивать адрес со строкой запроса.

headers — словарь HTTP-заголовков. Заголовок User-Agent описывает клиент. Не следует выдавать учебный идентификатор за официальный браузер или пытаться обходить защиту сервиса.

Почему словари удобны? Они явно связывают имя параметра с его значением. Код легче читать и изменять, чем длинную строку с вручную собранным URL.

### 7.6. Отправляем запрос

~~~python
response = httpx.get(
    SEARCH_URL,
    params=params,
    headers=headers,
    timeout=10.0,
    follow_redirects=True,
)
~~~

httpx.get() отправляет GET-запрос.

- SEARCH_URL — адрес поисковой страницы;
- params=params — параметры запроса;
- headers=headers — заголовки;
- timeout=10.0 — ограничение ожидания;
- follow_redirects=True — разрешение автоматически переходить по HTTP-перенаправлениям.

**Перенаправление (redirect)** — ответ сервера, указывающий клиенту перейти на другой URL. Клиент может автоматически следовать таким указаниям. В учебном примере это упрощает запрос, но в реальном инструменте необходимо отдельно контролировать перенаправления и не разрешать переходы на опасные внутренние адреса. Эту защиту подробно реализуем в уроке по безопасности.

Именованные аргументы вида timeout=10.0 делают назначение параметров понятным. Тайм-аут нужен, чтобы сетевой запрос не ожидался бесконечно.

### 7.7. Проверяем статус ответа

~~~python
response.raise_for_status()
~~~

Метод проверяет HTTP-статус. Если сервер вернул статус ошибки, httpx возбуждает HTTPStatusError. Это позволяет не обрабатывать страницу отказа так, будто она является обычной поисковой выдачей.

При этом статус 200 не доказывает, что мы получили именно выдачу. Сервер может вернуть HTML-страницу проверки, ограничений или сообщения об ошибке с успешным HTTP-статусом. Поэтому после проверки статуса нужно проверить, удалось ли найти ожидаемые элементы HTML.

### 7.8. Разбираем HTML

~~~python
soup = BeautifulSoup(response.text, "html.parser")
results = []
~~~

response.text — тело ответа, представленное как текст.

BeautifulSoup(...) создаёт объект для анализа HTML. Аргумент "html.parser" указывает использовать встроенный HTML-парсер Python.

**Парсер** — программа или компонент, который разбирает данные определённого формата. Вместо ручного поиска подстрок мы получаем объект, в котором можно искать элементы по селекторам.

results = [] создаёт пустой список. Позже будем добавлять в него словари с найденными результатами.

### 7.9. Перебираем найденные блоки

~~~python
for item in soup.select(".result"):
~~~

**for** — цикл, который последовательно перебирает элементы коллекции. soup.select(".result") находит элементы, соответствующие CSS-селектору .result, и возвращает их коллекцию.

На каждой итерации переменная item указывает на очередной блок результата.

**Новый приём: CSS-селектор** — это не оператор Python, а язык описания того, какие элементы нужно выбрать из HTML. Селектор .result выбирает класс result. Использование селекторов удобнее ручного перебора всех тегов, когда нужные элементы имеют известные классы.

### 7.10. Ищем заголовок и описание

~~~python
title_link = item.select_one(".result__title a")
snippet_element = item.select_one(".result__snippet")
~~~

select_one() возвращает первый элемент, подходящий под селектор, либо None, если элемент не найден.

Заголовок берём из ссылки внутри блока заголовка. Сниппет — из элемента с классом result__snippet.

**None** — специальное значение Python, означающее отсутствие значения. Элемент может отсутствовать, потому что провайдер изменил HTML, результат неполный или страница не является ожидаемой выдачей.

### 7.11. Пропускаем неподходящий результат

~~~python
if title_link is None:
    continue
~~~

if проверяет условие. Оператор сравнения **is** проверяет идентичность объекта. Выражение title_link is None — стандартный способ проверить, что переменная содержит именно None.

**continue** — оператор управления циклом. Он прекращает обработку текущей итерации и переходит к следующему элементу цикла. В отличие от break, он не завершает весь цикл.

Почему continue полезен? Если у блока нет ссылки с заголовком, мы пропускаем его, не вкладывая весь остальной код в дополнительные условия. Это помогает сохранить структуру цикла простой.

### 7.12. Извлекаем текст и URL

~~~python
title = title_link.get_text(" ", strip=True)
url = title_link.get("href", "").strip()
snippet = (
    snippet_element.get_text(" ", strip=True)
    if snippet_element is not None
    else ""
)
~~~

get_text(" ", strip=True) извлекает текст из элемента. Первый аргумент " " задаёт разделитель между фрагментами текста внутри вложенных элементов. strip=True просит удалить лишние пробелы по краям.

get("href", "") получает значение атрибута href. Второй аргумент — значение по умолчанию: если атрибута нет, возвращается пустая строка. Это позволяет не получать ошибку только из-за отсутствующего атрибута.

**if ... else ... внутри выражения** — условное выражение. Оно выбирает одно из двух значений: если snippet_element существует, извлекаем текст; иначе используем пустую строку.

Условное выражение полезно, когда нужно выбрать значение компактно. Если логика станет сложнее, лучше переписать её обычным блоком if/else, чтобы код оставался понятным.

В этой версии url берётся непосредственно из href. Некоторые поисковые сервисы используют промежуточные ссылки перенаправления. Если в результате окажется ссылка на сам поисковый сервис, её потребуется нормализовать и извлечь конечный адрес. Конкретная обработка зависит от фактического формата ссылок провайдера; не следует считать внутреннюю структуру поисковой страницы неизменной.

### 7.13. Проверяем поля и собираем словарь

~~~python
if not title or not url:
    continue

results.append(
    {
        "title": title,
        "url": url,
        "snippet": snippet,
    }
)
~~~

if not title or not url проверяет, что хотя бы одно обязательное поле пустое. or — логический оператор «ИЛИ»: всё выражение истинно, если истинно хотя бы одно из условий. Если заголовок или URL отсутствует, текущий элемент пропускается.

**append()** — метод списка, добавляющий один элемент в конец. Мы добавляем словарь с тремя ключами: title, url, snippet.

Почему словарь? У результата есть несколько связанных полей. Словарь позволяет обращаться к ним по понятным именам, например result["title"], вместо запоминания числовых индексов. Список словарей также удобно будет возвращать через MCP и преобразовывать в JSON-подобную структуру.

### 7.14. Ограничиваем число результатов

~~~python
if len(results) >= max_results:
    break
~~~

len(results) возвращает количество элементов в списке.

**>=** — оператор сравнения «больше или равно». Если количество результатов достигло заданного лимита, условие истинно.

**break** — оператор досрочного завершения цикла. Он останавливает перебор результатов. Это позволяет не продолжать работу, когда нужное количество уже собрано.

Зачем ограничивать результаты? Слишком длинная выдача увеличивает время обработки, расход памяти и объём ответа, который позже получит языковая модель. Для инструмента разумный лимит особенно важен: модели обычно полезнее несколько качественных результатов, чем сотни ссылок.

Учебный код предполагает, что max_results — положительное целое число. В следующем улучшении мы добавим проверку параметра, чтобы отрицательные значения и неожиданные типы не приводили к странному поведению.

### 7.15. Возвращаем список

~~~python
return results
~~~

return завершает функцию и возвращает собранный список вызывающему коду. Это не то же самое, что print(): вывод в терминал предназначен для человека, а возвращённые данные можно использовать дальше в программе.

Функция поиска не должна быть привязана к способу отображения результатов. Позже её вызовет MCP-инструмент, а не только терминал. Поэтому разделяем логику поиска и демонстрационный вывод.

### 7.16. Точка входа программы

~~~python
if __name__ == "__main__":
    search_query = input("Введите поисковый запрос: ")
    search_results = web_search(search_query)
~~~

Это важная конструкция Python.

__name__ — специальная переменная, которую Python создаёт для модуля. Когда файл запускают напрямую, значение обычно равно "__main__". Когда файл импортируют из другого модуля, значение будет именем модуля.

Условие if __name__ == "__main__": означает: «выполняй демонстрационный код только при прямом запуске этого файла».

Почему это преимущество? Позже другой файл сможет импортировать web_search и использовать функцию, не запуская сразу интерактивный вопрос input(). Такое разделение особенно полезно при тестировании и интеграции с MCP.

input() показывает приглашение и ждёт текст пользователя. Возвращённое значение сохраняется в search_query, затем передаётся в функцию.

### 7.17. Вывод результатов

~~~python
if not search_results:
    print("Результаты не найдены или поисковая страница не содержит ожидаемых блоков.")
else:
    for number, result in enumerate(search_results, start=1):
        print(f"{number}. {result['title']}")
        print(f"   URL: {result['url']}")
        print(f"   Описание: {result['snippet']}")
        print()
~~~

if not search_results проверяет, пуст ли список. Пустые коллекции в Python считаются ложными, поэтому условие истинно, когда результатов нет.

else задаёт альтернативную ветку: она выполняется, если список не пуст.

**enumerate()** — встроенная функция Python, которая при переборе выдаёт одновременно элемент и его порядковый номер. Аргумент start=1 задаёт нумерацию с единицы, привычную для списка результатов. Без enumerate() пришлось бы вручную вести отдельный счётчик.

**number, result** — распаковка пары значений, получаемой от enumerate(). На каждой итерации number содержит номер, а result — словарь результата.

F-строки, например f"{number}. {result['title']}", позволяют вставлять значения переменных и выражений прямо в строку.

print() без аргументов выводит пустую строку, чтобы отделить результаты друг от друга.

## 8. Обрабатываем ошибки провайдера

В первой версии сетевые ошибки могут прервать программу и вывести трассировку. На основе урока 7 улучшим функцию, обработав ожидаемые ошибки.

Внутри web_search() оберните сетевой запрос, проверку статуса и разбор ответа в try/except. Например:

~~~python
try:
    response = httpx.get(
        SEARCH_URL,
        params=params,
        headers=headers,
        timeout=10.0,
        follow_redirects=True,
    )
    response.raise_for_status()
except httpx.HTTPStatusError as error:
    print(f"Поисковый сервис вернул HTTP {error.response.status_code}")
    return []
except httpx.RequestError as error:
    print(f"Не удалось выполнить поисковый запрос: {error}")
    return []
~~~

Это пример учебной обработки, но у неё есть архитектурный недостаток: print() внутри функции смешивает поиск с диагностическим выводом. Для временной консольной программы это приемлемо, но при интеграции с MCP стандартный вывод может использоваться для обмена сообщениями протокола. В таком сервере нельзя бездумно печатать диагностические сообщения в stdout.

Для будущей MCP-версии лучше использовать структурированный результат, который явно содержит состояние и сообщение об ошибке, либо механизм логирования, направленный в stderr. В этом уроке важно понять саму разницу: **пользовательский результат** возвращается из функции, а **диагностика** предназначена для разработчика.

Также важно различать три ситуации:
1. Сетевая ошибка — соединение не удалось установить, произошёл тайм-аут и т. п.
2. HTTP-ошибка — сервис ответил статусом ошибки, например 429 или 503.
3. Неожиданная структура страницы — HTTP-ответ получен, но ожидаемые HTML-блоки не найдены.

Третья ситуация не всегда вызывает исключение. Поэтому пустой список сам по себе не доказывает, что в интернете ничего не найдено: возможно, сервис поменял HTML, вернул страницу проверки или не разрешил запрос. В реальной программе полезно различать «нет результатов» и «не удалось разобрать выдачу».

## 9. Ограничения HTML-поиска

Учебный пример обращается к HTML-странице выдачи. У такого решения есть ограничения:

- провайдер может изменить HTML-классы и структуру страницы;
- автоматизированные запросы могут ограничиваться или блокироваться;
- правила использования сервиса могут ограничивать автоматический сбор результатов;
- выдача может отличаться по региону, языку и времени;
- промежуточные ссылки могут требовать преобразования в конечные URL;
- HTML-страница может быть получена успешно, но не содержать результатов в ожидаемом формате.

Если поиск нужен для постоянной эксплуатации, следует проверить правила провайдера и рассмотреть официальный API с документированными лимитами и условиями. Отсутствие обязательного API-ключа в учебном примере не означает отсутствия условий использования или гарантированной стабильности.

Не пытайтесь обходить CAPTCHA, блокировки или другие механизмы доступа. При ограничениях корректное решение — использовать разрешённый интерфейс, официальный API или другой подходящий провайдер.

## 10. Следующее улучшение: проверяем лимит

Чтобы функция была надёжнее, можно добавить в начало:

~~~python
if not isinstance(max_results, int) or isinstance(max_results, bool):
    raise TypeError("max_results должен быть целым числом")

if max_results < 1:
    return []
~~~

**isinstance(value, type)** — встроенная функция, проверяющая, относится ли значение к указанному типу. Вторая проверка isinstance(max_results, bool) нужна потому, что в Python bool является подклассом int: без неё значения True и False могли бы пройти проверку как целые числа.

**raise** — ключевое слово, которое явно возбуждает исключение. Здесь TypeError означает, что передан аргумент неподходящего типа.

Почему мы используем raise, а не возвращаем пустой список при любом неправильном параметре? Пустой список обычно означает отсутствие результатов, а неверный тип параметра — ошибка вызова функции. Это разные ситуации. Явное исключение помогает быстрее обнаружить ошибку в коде, который вызывает функцию.

При этом max_results < 1 здесь трактуется как просьба не возвращать результаты. В более строгом интерфейсе можно вместо пустого списка тоже возбуждать ValueError — исключение для значения, которое имеет правильный тип, но недопустимо. Главное — выбрать понятное и последовательное поведение.

## 11. Типичные проблемы и диагностика

**ModuleNotFoundError: No module named 'bs4'.** Установите пакет beautifulsoup4 именно в активное виртуальное окружение: python -m pip install beautifulsoup4.

**HTTP 403 или 429.** Сервис отказывает в доступе или ограничивает частоту запросов. Не пытайтесь обходить запрет. Проверьте правила использования, частоту обращений и возможность официального API.

**Тайм-аут или ошибка соединения.** Проверьте подключение к сети, доступность домена, настройки прокси и корпоративные ограничения.

**Результатов нет, хотя поиск в браузере показывает выдачу.** HTML-сервис может отдавать другую разметку, страницу проверки или вариант страницы для другого клиента. Сначала проверьте response.status_code, тип ответа и начало response.text, не выводя чрезмерно большие объёмы данных. Не публикуйте в логах секреты, cookies или заголовки авторизации.

**Название найдено, а URL ведёт на поисковый сервис.** Провайдер может использовать промежуточную ссылку. Посмотрите фактическое значение href и реализуйте нормализацию согласно текущему формату провайдера.

**Страница содержит много лишнего текста.** Это одна из причин, почему мы извлекаем отдельные элементы HTML, а не возвращаем весь документ. В следующем уроке займёмся web_fetch: загрузим выбранную страницу и извлечём из неё читаемый текст.
