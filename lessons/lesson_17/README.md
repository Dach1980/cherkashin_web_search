# Урок 17. Надёжность веб-поиска и извлечения текста

## Цель урока

Успешный HTTP-запрос ещё не означает, что инструмент получил полезный текст. Сайт может вернуть пустую страницу, CAPTCHA, сообщение об ограничении, PDF вместо HTML, нечитаемые символы или HTML-оболочку без основного содержимого. В этом уроке мы научимся различать эти ситуации, проверять результат и возвращать понятную диагностику.

После урока вы сможете проверять статус HTTP, Content-Type, пустое содержимое и подозрительные страницы блокировки; понимать разницу между байтами и строкой; объяснять роль кодировки; создавать воспроизводимые проверки без реального доступа к сайтам.

## 1. Термины

- **Reliability — надёжность:** способность системы стабильно давать полезный и корректный результат.
- **Web search — веб-поиск:** поиск страниц и получение списка результатов со ссылками и фрагментами.
- **Web fetch — получение страницы:** загрузка конкретного URL для чтения содержимого.
- **HTTP (Hypertext Transfer Protocol):** протокол обмена запросами и ответами между клиентом и сервером.
- **HTTP status code — код состояния HTTP:** число, описывающее результат запроса. Например, 200 — запрос формально успешен, 403 — доступ запрещён, 404 — ресурс не найден, 429 — слишком много запросов.
- **Content-Type:** HTTP-заголовок, сообщающий тип данных в ответе.
- **MIME type:** стандартизованное обозначение формата данных: text/html, text/plain, application/json, application/pdf.
- **Encoding — кодировка:** правило преобразования байтов в символы.
- **Bytes — байты:** данные в числовом представлении, часто используемом при передаче по сети.
- **Decoding — декодирование:** преобразование байтов в строку по выбранной кодировке.
- **Extraction — извлечение:** выделение полезного текста из HTML или другого документа.
- **HTML:** язык разметки, который описывает структуру веб-страницы, но не равен её читаемому тексту.
- **CAPTCHA:** проверка, призванная отличить человека от автоматизированного клиента.
- **Timeout — тайм-аут:** ограничение времени ожидания ответа.
- **Retry — повторная попытка:** повтор запроса после временной ошибки. Повторы должны быть ограничены.
- **Fallback — запасной путь:** заранее предусмотренный способ сообщить о проблеме или использовать альтернативный метод.
- **Diagnostic message — диагностическое сообщение:** объяснение того, что произошло и что инструмент смог сделать.
- **Heuristic — эвристика:** приближённое правило, полезное в практике, но не гарантирующее верный результат всегда.
- **False positive — ложноположительное срабатывание:** система объявила проблему, которой нет.
- **False negative — ложноотрицательное срабатывание:** система не заметила проблему, которая есть.
- **Unit test — модульный тест:** проверка отдельной функции или компонента.
- **Fixture — тестовые данные:** заранее подготовленные значения для теста.
- **Contract — контракт:** описание входных данных, результата и правил обработки ошибок функции.

## 2. Почему HTTP 200 недостаточно

Сервер может вернуть 200 OK и при этом отдать CAPTCHA, страницу проверки безопасности, пустую HTML-оболочку или текст «Доступ запрещён». Значит, HTTP-статус описывает результат передачи, но не доказывает, что получен нужный материал.

Надёжная обработка состоит из этапов:

1. Выполнить запрос и обработать сетевые ошибки.
2. Проверить HTTP-статус.
3. Проверить тип содержимого.
4. Декодировать байты в текст с учётом кодировки.
5. Извлечь читаемый текст из HTML.
6. Проверить, не пуст ли результат и не похож ли он на страницу блокировки.
7. Вернуть текст или ясную диагностику.

Не сводите все проблемы к сообщению «страница не найдена»: для разных причин нужны разные действия.

## 3. Основные статусы

| Статус | Значение | Реакция |
|---|---|---|
| 200 | Запрос формально успешен | Проверить тип и содержимое |
| 301, 302 | Перенаправление | Проверить, куда пришёл запрос |
| 403 | Доступ запрещён | Сообщить об ограничении, не обходить защиту |
| 404 | Ресурс не найден | Проверить адрес или доступность страницы |
| 429 | Слишком много запросов | Снизить частоту; учесть Retry-After |
| 500–599 | Ошибка сервера | Сообщить об ошибке; возможен ограниченный повтор |
| Тайм-аут | Ответ не получен вовремя | Выдать диагностику, не заявлять об успешном чтении |

Повторные запросы не должны быть бесконечными. Особенно важно не усиливать нагрузку на сервер после ответа 429.

## 4. Content-Type и неподдерживаемые форматы

Заголовок Content-Type может сообщить, что сервер вернул HTML (text/html), обычный текст (text/plain), JSON (application/json), PDF (application/pdf) или изображение (image/png).

Если наш инструмент извлекает текст только из HTML, нельзя передать PDF в HTML-парсер и назвать результат успешно прочитанным документом. Нужно вернуть категорию unsupported_content_type и объяснить, что формат пока не поддерживается. Это часть контракта инструмента: он должен честно описывать свои возможности.

Заголовок может быть ошибочным, поэтому в производственном коде его следует разбирать аккуратно. Но не надо без ограничений угадывать формат по содержимому.

## 5. Байты, строки и кодировки

Сетевой ответ часто приходит как байты. Чтобы получить строку Python, байты нужно декодировать. UTF-8 — распространённая кодировка Unicode; Unicode — стандарт представления символов разных письменностей. Неправильная кодировка может превратить русские буквы в нечитаемые символы.

В Python метод decode("utf-8") строго декодирует байты и при ошибке может вызвать UnicodeDecodeError. Параметр errors="replace" заменяет некорректные последовательности символом замены, а errors="ignore" пропускает их. Игнорирование может безвозвратно удалить важные данные. В реальном проекте сначала учитывают charset из ответа, а резервный вариант документируют явно. Не следует перебирать кодировки наугад, пока текст не покажется правдоподобным.

## 6. Пустой текст и CAPTCHA

После удаления HTML-тегов строка может оказаться пустой или состоять только из пробелов. Проверка not text.strip() выявляет такой результат: strip() удаляет пробельные символы по краям строки. Если полезного текста нет, верните empty_content, а не сообщение об успехе.

Страница CAPTCHA или блокировки тоже может выглядеть как обычный HTML. Для диагностики можно искать маркеры captcha, verify you are human, access denied и checking your browser. Но это эвристика, а не доказательство. Например, статья о защите от CAPTCHA может содержать это слово без всякой блокировки. Маркеры могут дать ложноположительное или ложноотрицательное срабатывание.

Не обходите CAPTCHA и другие средства защиты. Если сайт ограничил автоматическое получение содержимого, сообщите об этом честно.

## 7. Пример кода

В файле examples/lesson17_content_reliability.py будет классификатор, который не делает сетевых запросов. Он получает подготовленный результат и возвращает категорию. Это позволяет тестировать логику без интернета.

    from dataclasses import dataclass

    @dataclass
    class FetchResult:
        status_code: int
        content_type: str
        text: str

    def classify_fetch_result(result: FetchResult) -> str:
        if result.status_code == 403:
            return "access_forbidden"
        if result.status_code == 404:
            return "page_not_found"
        if result.status_code == 429:
            return "rate_limited"
        if result.status_code >= 500:
            return "server_error"
        if not 200 <= result.status_code < 300:
            return "http_error"

        normalized_type = result.content_type.casefold()
        if "text/html" not in normalized_type and "text/plain" not in normalized_type:
            return "unsupported_content_type"
        if not result.text.strip():
            return "empty_content"

        lowered_text = result.text.casefold()
        block_markers = (
            "captcha",
            "verify you are human",
            "access denied",
            "checking your browser",
        )
        if any(marker in lowered_text for marker in block_markers):
            return "possible_block_page"
        return "ok"

    def main() -> None:
        samples = [
            FetchResult(200, "text/html; charset=utf-8", "<h1>Документация</h1>"),
            FetchResult(403, "text/html", "Access denied"),
            FetchResult(200, "application/pdf", ""),
            FetchResult(200, "text/html", "   \n  "),
            FetchResult(429, "text/html", "Too many requests"),
            FetchResult(200, "text/html", "Please verify you are human"),
        ]
        for sample in samples:
            print(sample.status_code, classify_fetch_result(sample))

    if __name__ == "__main__":
        main()

### Подробный разбор

**Импорт dataclass.** from dataclasses import dataclass подключает декоратор из стандартной библиотеки. Декоратор дополняет класс типичными методами, в том числе инициализацией полей, и избавляет от ручного написания конструктора.

**@dataclass.** Символ @ используется в синтаксисе декораторов. Класс FetchResult хранит три поля: код состояния, тип содержимого и текст.

**Аннотации типов.** status_code: int, content_type: str и text: str документируют ожидаемые типы. int — целое число, str — строка. Аннотации помогают читать код и редакторам, но сами по себе не гарантируют автоматическую проверку типа во время выполнения.

**Сигнатура функции.** def classify_fetch_result(result: FetchResult) -> str объявляет функцию, которая принимает объект FetchResult и возвращает строку. Часть -> str — аннотация возвращаемого типа.

**Оператор ==.** Выражение result.status_code == 403 сравнивает значения. Не путайте == с =: двойной знак проверяет равенство, одиночный присваивает значение.

**Оператор >=.** Условие result.status_code >= 500 означает «больше или равно». В этом примере все коды от 500 и выше считаются серверной ошибкой. При необходимости можно точнее проверить диапазон 500 <= status_code < 600.

**Цепное сравнение и not.** Выражение not 200 <= result.status_code < 300 читается как «статус не находится в диапазоне 200–299». Цепные сравнения в Python компактны и читаются как математическое выражение. not меняет истинность условия на противоположную.

**Операторы in, not in и and.** Проверка "text/html" not in normalized_type означает, что подстрока отсутствует. and требует, чтобы оба условия были истинными. Таким образом, неподдерживаемый формат фиксируется, только если это не HTML и одновременно не обычный текст.

**Метод casefold().** Нормализует регистр для сравнения строк. Он универсальнее lower() для некоторых символов разных языков. Мы создаём копию для проверки, а исходное значение не меняем.

**Метод strip().** not result.text.strip() выявляет пустую строку, в том числе строку, содержащую только пробелы и переводы строк.

**Кортеж block_markers.** Круглые скобки с несколькими строками образуют кортеж — упорядоченную неизменяемую последовательность. Он подходит для фиксированного набора маркеров.

**Новая конструкция any() с выражением for.** any(marker in lowered_text for marker in block_markers) спрашивает, есть ли хотя бы один маркер в тексте. Выражение for marker in block_markers перебирает маркеры, а any() возвращает True, как только находит истинный результат. Это короче ручного цикла с отдельной переменной-флагом. Однако маркеры только указывают на возможную блокировку, а не доказывают её.

**Список samples и цикл for.** Квадратные скобки создают список примеров. Конструкция for sample in samples перебирает их по очереди. print(sample.status_code, classify_fetch_result(sample)) выводит HTTP-статус и результат классификации.

**Условие __name__ == "__main__".** При прямом запуске Python присваивает __name__ значение "__main__". При импорте из другого файла условие обычно ложно. Это позволяет использовать файл и как самостоятельную программу, и как модуль.

## 9. Ограничения примера

1. Функция классифицирует уже полученный результат; она не выполняет HTTP-запрос.
2. В реальном сервере текст появляется после декодирования и извлечения.
3. Проверка Content-Type по подстроке учебная; производственный код должен аккуратно разбирать MIME-тип и параметры после точки с запятой.
4. Маркеры CAPTCHA могут ошибаться.
5. Не записывайте целиком все страницы в журнал: они могут содержать персональные данные, секреты или очень много текста.
6. Не обходите CAPTCHA и другие средства защиты.
7. Ограничивайте повторы, особенно после 429.

## 10. Последовательность в настоящем MCP-инструменте

1. Проверить URL и ограничения безопасности.
2. Выполнить HTTP-запрос с тайм-аутом.
3. Обработать сетевые исключения.
4. Проверить HTTP-статус.
5. Проверить Content-Type.
6. Декодировать байты с учётом charset.
7. Извлечь текст, если формат поддерживается.
8. Проверить пустой результат и признаки блокировки.
9. Ограничить размер текста.
10. Вернуть содержимое вместе с ясной диагностикой.

Не маскируйте неудачу под успех. Если текст не получен, инструмент должен прямо сказать об этом. Иначе модель может повторять запрос, делать неверные выводы или отвечать из памяти, полагая, что получила источник.

## Итог
