## 1. Что мы устанавливаем и зачем

Для разработки понадобятся несколько компонентов. Они связаны друг с другом, но выполняют разные задачи.

### 1.1. Python

**Python** — язык программирования, на котором мы будем писать код нашего сервера.

Чтобы выполнить файл Python, компьютеру нужен **интерпретатор** — программа, которая читает и выполняет инструкции Python. Сам по себе текстовый файл с расширением `.py` не является готовым приложением Windows.

### 1.2. Visual Studio Code

**Visual Studio Code (VS Code)** — редактор кода. В нём удобно создавать и редактировать файлы, подсвечивать синтаксис, находить ошибки и запускать команды.

VS Code не заменяет Python. Если установить только редактор, код можно будет написать, но для его выполнения потребуется отдельно установленный интерпретатор.

### 1.3. Расширение Python для VS Code

**Расширение (extension)** — дополнительный модуль, который добавляет редактору возможности. Расширение Python помогает VS Code распознавать Python-код, выбирать интерпретатор, запускать файлы и использовать инструменты диагностики.

Расширение не заменяет сам Python: это отдельные компоненты.

### 1.4. PowerShell

**PowerShell** — командная оболочка Windows, в которой можно вводить команды для запуска программ, перехода между папками и управления окружением.

**Терминал (terminal)** — интерфейс для ввода текстовых команд. В VS Code есть встроенный терминал, поэтому не обязательно каждый раз открывать отдельное окно PowerShell.

### 1.5. Как компоненты работают вместе

```text
Вы пишете код в VS Code
        |
        v
Расширение Python помогает редактору
выбрать нужный интерпретатор
        |
        v
Интерпретатор Python выполняет файл
        |
        v
Результат или сообщение об ошибке
появляется в терминале
```

Итак, роли разные:

- Python — язык и среда выполнения;
- интерпретатор — выполняет Python-код;
- VS Code — редактор, в котором мы работаем;
- расширение Python — добавляет редактору функции для Python;
- PowerShell — оболочка, в которой мы выполняем команды.

## 2. Основные термины

**Интерпретатор (interpreter)** — программа, которая выполняет инструкции языка программирования.

**Редактор кода (code editor)** — программа для создания и изменения исходного кода.

**IDE (Integrated Development Environment)** — интегрированная среда разработки. Обычно объединяет редактор, запуск, отладку и другие инструменты. VS Code является редактором, но с расширениями может предоставлять многие функции среды разработки.

**Командная оболочка (shell)** — программа, которая интерпретирует введённые команды. PowerShell — одна из оболочек Windows.

**Исходный код (source code)** — текст программы, написанный разработчиком. Например, файл `main.py`.

**Путь (path)** — адрес файла или папки в файловой системе. Например, `D:\\Projects\\cherkashin_web_search` — возможный путь к проекту на диске D. У вас путь может быть другим.

**Окружение (environment)** — набор программ и настроек, с которыми запускается приложение.

**Виртуальное окружение (virtual environment)** — изолированное окружение Python для конкретного проекта. Оно позволяет устанавливать библиотеки проекта отдельно от библиотек других программ. Сегодня мы его создадим, а подробно изучим на уроке № 6.

## 3. Проверяем, установлен ли Python

Не устанавливайте Python повторно, пока не проверили, есть ли он уже на компьютере. Возможно, он установлен и готов к работе.

### Шаг 1. Откройте PowerShell

В Windows можно нажать клавишу Windows, начать вводить `PowerShell` и открыть Windows PowerShell или PowerShell.

Можно также открыть VS Code, если он уже установлен, и выбрать в меню **Terminal → New Terminal** («Терминал → Создать терминал»).

### Шаг 2. Выполните команду проверки

Введите:

```powershell
python --version
```

Если команда не сработала, попробуйте:

```powershell
py --version
```

Возможный результат:

```text
Python 3.11.7
```

Это пример результата, а не требование установить именно эту версию. Для курса желательно использовать актуальную стабильную версию Python 3, совместимую с выбранными библиотеками. Если проект или библиотека потребуют конкретную версию, мы отдельно зафиксируем её.

### Разбор команды

`python --version`

- `python` — имя команды, которая запускает интерпретатор Python, если она настроена в системе;
- пробел разделяет имя команды и аргумент;
- `--version` — аргумент командной строки, который просит программу вывести её версию.

**Аргумент командной строки** — дополнительное значение, которое передаётся программе при запуске и меняет её действие.

Здесь `--version` — не оператор Python. Это параметр запуска самой программы Python. Такой вариант записи важно отличать от операторов внутри файла `.py`.

Команда `py --version` использует Windows Python Launcher, если он установлен. На некоторых компьютерах доступна команда `py`, на других — только `python`. Отсутствие одной команды ещё не доказывает, что Python полностью отсутствует.

### Шаг 3. Проверяем, откуда запускается Python

В PowerShell выполните:

```powershell
where.exe python
where.exe py
```

Команда `where.exe` ищет исполняемые файлы с указанным именем по путям, известным Windows. Она может вывести один или несколько путей.

Если вместо ожидаемого пути появляется путь к WindowsApps или открывается Microsoft Store, это может быть связано с псевдонимом запуска приложения Windows, а не с полноценной установкой Python. В таком случае проверьте наличие установленного интерпретатора и настройки **App execution aliases** в Windows.

Не нужно пугаться, если одна из команд ничего не вывела: это диагностический шаг. Главное — выяснить, каким способом Python запускается на вашем компьютере.

## 4. Устанавливаем Python, если он отсутствует

Если проверка не обнаружила рабочий интерпретатор, скачайте установщик с официального сайта:

- Python: https://www.python.org/downloads/windows/

Скачивайте установщик с официального сайта Python или используйте другой доверенный официальный канал распространения. Не скачивайте установщики с неизвестных сайтов.

### Шаг 1. Запустите установщик

Откройте скачанный файл установки Python.

В установщике Windows обратите внимание на пункт **Add Python to PATH**, если он предлагается. Для обычной установки это помогает запускать Python из терминала командой `python`, не указывая полный путь к исполняемому файлу.

**PATH** — переменная среды, в которой Windows хранит список каталогов для поиска запускаемых программ. Если каталог Python доступен через PATH, команда `python` обычно работает из разных папок.

Если вы не включили этот пункт, Python иногда всё равно можно запускать через команду `py` или через полный путь, но начинающему проще настроить стандартный запуск сразу.

Завершите установку. Если установщик предлагает отключить ограничение длины путей, это может помочь некоторым Python-пакетам, но не является обязательным действием для первого запуска.

### Шаг 2. Откройте новое окно терминала

После установки закройте старое окно PowerShell и откройте новое. Новое окно считывает актуальные переменные среды.

Проверьте:

```powershell
python --version
python -m pip --version
```

Первая команда должна показать версию Python. Вторая проверяет доступность инструмента установки Python-пакетов `pip` через выбранный интерпретатор.

**pip** — стандартный инструмент для установки и управления Python-пакетами из пакетных источников.

Если команда `python` не работает, попробуйте `py --version`. Если ни одна команда не срабатывает, не устанавливайте подряд несколько копий Python: сначала нужно проверить, куда установлена программа и как настроен PATH.

## 6. Устанавливаем расширение Python

1. В VS Code откройте раздел **Extensions**. Обычно это значок из нескольких блоков на боковой панели.
2. В поле поиска введите `Python`.
3. Выберите расширение **Python**, издатель — **Microsoft**.
4. Нажмите **Install** («Установить»).
5. Дождитесь завершения установки.

Расширение помогает редактору распознавать Python-файлы, выбирать интерпретатор и запускать код. При необходимости оно может предложить установить дополнительные компоненты, например поддержку проверки типов или форматирования. Для первого запуска они не обязательны.

### Выбираем интерпретатор в VS Code

После установки Python и расширения:

1. Откройте командную палитру через `Ctrl+Shift+P`.
2. Введите `Python: Select Interpreter`.
3. Выберите установленный интерпретатор Python.

**Командная палитра (Command Palette)** — поиск и запуск команд самого VS Code. Сочетание клавиш `Ctrl+Shift+P` открывает её на Windows.

Если позже мы создадим виртуальное окружение проекта, в списке может появиться отдельный интерпретатор из этого окружения. Для проекта предпочтительно выбирать именно его, чтобы запуск и установка библиотек использовали одну и ту же среду.

## 8. Создаём первый Python-файл

В VS Code в панели Explorer:

1. Найдите корневую папку проекта.
2. Создайте новый файл с именем `main.py`.
3. Вставьте код:

```python
print("Привет! Python работает.")
print("Мы готовим MCP-сервер для LM Studio.")
```

Сохраните файл сочетанием клавиш `Ctrl+S`.

### Разбираем код построчно

Первая строка:

```python
print("Привет! Python работает.")
```

- `print` — встроенная функция Python, которая выводит данные в стандартный поток вывода; в нашем случае текст появится в терминале.
- Круглые скобки `()` указывают, что мы вызываем функцию и передаём ей значение.
- Двойные кавычки `"` обозначают начало и конец строкового значения.
- `Привет! Python работает.` — строка, которую мы передаём функции.
- Закрывающая скобка завершает вызов функции.

**Строка (string)** — тип данных для текста. Например, `"Привет"` — строка.

Вторая строка работает так же, но выводит другое сообщение:

```python
print("Мы готовим MCP-сервер для LM Studio.")
```

### Какие операторы мы использовали?

В этом примере мы пока не использовали арифметические или логические операторы. Мы использовали **вызов функции** — запись имени функции с круглыми скобками и передаваемыми аргументами.

Это важное различие: `print(...)` — не оператор присваивания и не специальная команда PowerShell, а вызов встроенной функции Python.

**Аргумент функции** — конкретное значение, переданное функции при вызове. В нашем примере аргументом является строка в кавычках.

Почему используем `print()`? Потому что в первых уроках нам нужен простой способ увидеть результат выполнения программы. Функция позволяет проверить, что файл запускается и интерпретатор выполняет код. Позже мы будем возвращать результаты функций и передавать данные между частями приложения, а не только печатать их в терминал.

### Разбор команды запуска

`python main.py`

- `python` — запускает интерпретатор;
- `main.py` — имя файла, который нужно выполнить.

Между ними стоит пробел, который отделяет команду от аргумента. В отличие от `--version`, здесь аргумент — путь к файлу с кодом.

Важное преимущество такого способа запуска — прозрачность. Мы явно видим, какой интерпретатор и какой файл запускаем. Это помогает позже разбираться с окружениями и зависимостями.

## 10. Первое знакомство с командами PowerShell

В следующих уроках мы будем часто вводить команды. Сейчас разберём несколько основных.

### Узнать текущую папку

```powershell
Get-Location
```

Команда выводит путь к текущей рабочей папке.

### Посмотреть файлы и папки

```powershell
Get-ChildItem
```

Она показывает содержимое текущей папки. В PowerShell также работает короткая команда `dir`.

### Перейти в папку

```powershell
Set-Location D:\\Projects\\cherkashin_web_search
```

Замените путь на фактический путь к вашей папке.

Сокращённая команда PowerShell — `cd`. Например:

```powershell
cd D:\\Projects\\cherkashin_web_search
```

**Текущая рабочая папка** — каталог, относительно которого выполняются многие команды и разрешаются относительные пути. Если терминал находится не там, команда `python main.py` может сообщить, что файл не найден, даже если файл существует в другой папке.

### Очистить экран

```powershell
Clear-Host
```

Также обычно доступна команда `cls`. Она очищает отображение терминала, но не удаляет файлы и не отменяет ранее выполненные действия.

### Что такое относительный и абсолютный путь

**Абсолютный путь** указывает полный адрес файла или папки, например `D:\\Projects\\cherkashin_web_search\\main.py`.

**Относительный путь** задаётся относительно текущей папки. Если терминал находится в корне проекта, файл можно указать коротко: `main.py`.

Относительные пути удобны для команд и кода, потому что проект можно разместить в другой папке, не переписывая каждый путь вручную. Но важно понимать, от какой рабочей папки они считаются.

## 11. Создаём виртуальное окружение проекта

Сейчас создадим виртуальное окружение, чтобы проект мог использовать собственные зависимости.

Находясь в корне репозитория, выполните:

```powershell
python -m venv .venv
```

Если вместо `python` у вас используется команда `py`, допустим вариант:

```powershell
py -m venv .venv
```

Эта команда создаёт папку `.venv` с окружением Python.

### Разбираем новую конструкцию

В команде:

`python -m venv .venv`

- `python` запускает интерпретатор;
- `-m` просит Python запустить указанный модуль как программу;
- `venv` — стандартный модуль Python для создания виртуальных окружений;
- `.venv` — имя папки, в которой будет создано окружение.

Обратите внимание: `-m` — параметр командной строки Python, а не оператор внутри Python-кода.

**Модуль (module)** — компонент Python, который содержит код и может использоваться или запускаться как отдельная единица. Модуль `venv` входит в стандартную поставку Python и предназначен для создания виртуальных окружений.

Почему используем `python -m venv`, а не устанавливаем отдельную программу? Потому что `venv` — стандартный инструмент Python. Такой способ явно связывает создание окружения с тем интерпретатором, который мы вызвали командой `python`.

### Активируем окружение

В PowerShell выполните:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если активация прошла успешно, в начале строки терминала обычно появляется префикс `(.venv)`.

**Активация** изменяет настройки текущего терминала так, чтобы команды Python и установки пакетов по умолчанию использовали виртуальное окружение проекта. Это удобство для разработчика; сам Python-код не становится другим.

Если PowerShell сообщает, что выполнение сценариев запрещено, это связано с политикой выполнения PowerShell. Не нужно бездумно менять системную политику. В учебном окружении можно либо использовать разрешённый организационными настройками способ активации, либо запускать интерпретатор напрямую по пути `.venv\\Scripts\\python.exe`. Например:

```powershell
.\.venv\Scripts\python.exe --version
```

Этот вариант позволяет проверить интерпретатор окружения без активации.

### Проверяем окружение

После активации выполните:

```powershell
python --version
python -m pip --version
```

Затем в VS Code снова откройте командную палитру `Ctrl+Shift+P`, выберите `Python: Select Interpreter` и укажите интерпретатор из папки `.venv`, если он ещё не выбран.

### Почему папка называется `.venv`

Имя `.venv` — общепринятая договорённость, а не обязательное слово языка. Точка в начале имени обычно делает папку менее заметной в некоторых инструментах, а имя подсказывает разработчику, что внутри виртуальное окружение.

Папку окружения обычно не добавляют в Git-репозиторий: её можно заново создать на другом компьютере. Именно поэтому в проекте будет файл `.gitignore`, который исключает временные и локальные файлы из контроля версий.

## 12. Типичные ошибки и способы их исправления

### Ошибка 1. «python не является внутренней или внешней командой»

Причина: Windows не находит Python по команде `python`.

Что проверить:

1. Выполните `py --version`.
2. Проверьте, установлен ли Python.
3. Откройте новое окно терминала после установки.
4. Проверьте PATH и настройки псевдонимов запуска приложений Windows.

Не нужно сразу переустанавливать всё подряд. Сначала определите, отсутствует ли интерпретатор или проблема только в команде запуска.

### Ошибка 2. «can't open file 'main.py'»

Причина: интерпретатор не нашёл файл по указанному пути.

Что сделать:

1. Выполните `Get-Location`, чтобы проверить текущую папку.
2. Выполните `Get-ChildItem`, чтобы посмотреть список файлов.
3. Убедитесь, что файл действительно называется `main.py`, а не `main.py.txt`.
4. Перейдите в папку, где находится файл, или укажите правильный путь.

### Ошибка 3. В редакторе подчёркнуты импорты или не выбран Python

Причина может быть в том, что VS Code выбрал другой интерпретатор.

Откройте командную палитру и выполните `Python: Select Interpreter`. Выберите окружение проекта, если оно создано. Убедитесь, что пакеты установлены именно в этом окружении, а не в другой копии Python.

### Ошибка 4. PowerShell запрещает запуск Activate.ps1

Это не обязательно означает, что Python установлен неправильно. PowerShell может ограничивать выполнение сценариев в соответствии с настройками безопасности.

Для проверки можно запустить:

```powershell
.\.venv\Scripts\python.exe --version
```

Если команда работает, окружение существует. Не меняйте глобальные настройки безопасности без понимания последствий и без необходимости.

### Ошибка 5. Программа ничего не выводит

Проверьте:

- сохранён ли файл;
- действительно ли в нём есть вызов `print()`;
- запущен ли нужный файл;
- нет ли ошибки в терминале;
- не редактируете ли вы одну копию файла, а запускаете другую.

### Ошибка 6. Python работает, но библиотека не найдена

Сообщение вроде `ModuleNotFoundError` означает, что Python не смог найти импортируемый модуль. Частая причина — пакет установлен в другом окружении.

В следующих уроках мы научимся устанавливать зависимости через `python -m pip` и проверять, какой интерпретатор используется. Важно запускать `pip` через тот же Python, которым выполняется проект.
