# Спецификация проекта MCP Web Search

## Назначение
Создать Python MCP-сервер для LM Studio с двумя инструментами:
- `search_web` — ищет страницы и возвращает структурированный список результатов.
- `fetch_web_page` — загружает страницу по URL и возвращает ограниченный объём читаемого текста.

Внутренние Python-функции реализации называются `web_search` и `web_fetch`; это не имена MCP-инструментов, видимые модели.

## Основной сценарий
1. Пользователь задаёт модели вопрос.
2. Модель при необходимости вызывает `search_web`.
3. Получает названия, URL и короткие описания страниц.
4. Выбирает подходящую страницу и вызывает `fetch_web_page`.
5. Использует извлечённый текст для ответа.

Сервер предоставляет инструменты; решение о вызове принимает модель.

## Архитектурные требования
- Python используется для прикладной логики.
- MCP SDK для Python отвечает за протокол и регистрацию инструментов.
- Поиск и загрузка страницы проверяются как независимые Python-функции.
- Сетевые операции имеют тайм-ауты и ограничения объёма.
- Ошибки возвращаются в понятном виде без раскрытия секретов и внутренних данных.
- Отладочные сообщения не пишутся в `stdout`, поскольку он используется транспортом `stdio`.
- Конфигурация отделена от логики; прямые зависимости зафиксированы в `requirements.txt`, тестовая — в `requirements-dev.txt`.
- Для текущей реализации используется MCP Python SDK 1.x; переход на SDK 2.x требует отдельной миграции и интеграционных тестов.

## Требования к search_web
- Проверять непустой запрос.
- Ограничивать число результатов.
- Возвращать единообразные поля: название, URL, фрагмент описания.
- Обрабатывать пустую выдачу, сетевые сбои и ошибки провайдера.
- Поиск использует DuckDuckGo HTML; доступность, антибот-защита и HTML-разметка внешнего сервиса могут меняться.

## Требования к fetch_web_page и безопасности
- Принимать корректный абсолютный HTTP(S) URL.
- Блокировать loopback, частные, link-local и другие запрещённые адреса.
- Проверять все полученные DNS-адреса; если хотя бы один ответ не является глобальным, отклонять запрос.
- Закреплять один из проверенных публичных IP непосредственно в URL сетевого запроса, чтобы HTTP-клиент не разрешал исходное имя повторно.
- Для HTTPS сохранять исходный hostname в заголовке `Host`, TLS SNI и проверке сертификата. Проверка TLS не отключается.
- При каждом редиректе заново проверять целевой URL и выполнять отдельное DNS-разрешение с последующим закреплением IP.
- Ограничивать время запроса, объём загружаемых данных и длину возвращаемого текста.
- Обрабатывать HTTP-ошибки, неподдерживаемые типы содержимого и пустой текст.
- Не выполнять загруженный код и не открывать локальные файлы по URL.
- Не доверять содержимому веб-страниц и не раскрывать секреты в ошибках.

## Конфигурация
Фактические переменные окружения:
- `WEB_TIMEOUT_SECONDS` (15)
- `WEB_SEARCH_MAX_RESULTS` (5)
- `WEB_FETCH_MAX_PAGE_CHARS` (12000)
- `WEB_FETCH_MAX_REDIRECTS` (3)
- `WEB_FETCH_MAX_RESPONSE_BYTES` (1000000)
- `WEB_SEARCH_LOG_LEVEL` (INFO)

Файл `.env` автоматически не загружается. В LM Studio настройки при необходимости передаются через объект `env` записи MCP-сервера. Для первого запуска допустимы значения по умолчанию.

## Тестирование
Покрыть проверку поискового запроса и URL, нормализацию результатов, пустую выдачу, сетевые ошибки, редиректы, лимиты, неподдерживаемые типы содержимого, регистрацию MCP-инструментов и цепочку `search_web → fetch_web_page`.

Для защиты от DNS rebinding тесты должны доказывать:
- сетевой запрос строится с IP-литералом, выбранным из проверенного DNS-ответа;
- исходное доменное имя остаётся в Host и TLS SNI;
- DNS не выполняется повторно HTTP-клиентом для исходного hostname;
- смешанный набор публичных и непубличных DNS-ответов отклоняется;
- каждый редирект проверяется отдельно до следующего сетевого запроса.

Автотесты должны использовать подменённые ответы и не зависеть от доступности внешнего поисковика. Отдельно необходим ручной сетевой smoke test. Unit-тесты не заменяют интеграцию с LM Studio и проверку упакованного приложения.

## Запуск и распространение
- LM Studio запускает сервер по stdio.
- Для коммерческого первого релиза сервер будет упакован для Windows x64 в ZIP-каталог; отдельный EXE-установщик не используется.
- Покупателю не требуются Python, Git, VS Code или командная строка.
- Пример для разработки с виртуальным окружением не является конфигурацией коммерческого ZIP.

## Критерии готовности
Оба инструмента доступны в LM Studio; поиск возвращает структурированные результаты; загрузка возвращает читаемый текст; модель выполняет цепочку поиска и загрузки; ошибки обрабатываются предсказуемо; DNS pinning и защитные ограничения покрыты тестами; сервер работает после закрытия VS Code и терминала; ZIP проходит чистую проверку на Windows 10/11 x64.
