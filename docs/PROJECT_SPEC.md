# Спецификация проекта MCP Web Search

## Назначение
Создать Python MCP-сервер для LM Studio с двумя инструментами:
- `web_search` — ищет страницы и возвращает структурированный список результатов.
- `web_fetch` — загружает страницу по URL и возвращает ограниченный объём читаемого текста.

## Основной сценарий
1. Пользователь задаёт модели вопрос.
2. Модель при необходимости вызывает `web_search`.
3. Получает названия, URL и короткие описания страниц.
4. Выбирает подходящую страницу и вызывает `web_fetch`.
5. Использует извлечённый текст для ответа.

Сервер предоставляет инструменты; решение о вызове принимает модель.

## Архитектурные требования
- Python используется для прикладной логики.
- MCP SDK для Python отвечает за протокол и регистрацию инструментов.
- Поиск и загрузка страницы сначала реализуются и проверяются независимо от MCP.
- Сетевые операции имеют тайм-ауты и ограничения объёма.
- Ошибки возвращаются в понятном виде без раскрытия секретов и внутренних данных.
- Отладочные сообщения не пишутся в `stdout`, поскольку он используется транспортом `stdio`.
- Конфигурация отделена от логики; зависимости описаны в `requirements.txt`.

## Требования к web_search
- Проверять непустой запрос.
- Ограничивать число результатов.
- Возвращать единообразные поля: название, URL, фрагмент описания.
- Обрабатывать пустую выдачу, сетевые сбои и ошибки провайдера.
- Выбрать провайдера без обязательного API-ключа и проверить его на этапе реализации. Доступность и условия внешних сервисов могут меняться.

## Требования к web_fetch и безопасности
- Принимать корректный абсолютный HTTP(S) URL.
- Блокировать loopback, частные, link-local и другие запрещённые адреса.
- Учитывать DNS-разрешение и повторно проверять адрес после редиректов.
- Ограничивать время запроса, объём загружаемых данных и длину возвращаемого текста.
- Обрабатывать HTTP-ошибки, неподдерживаемые типы содержимого и пустой текст.
- Не выполнять загруженный код и не открывать локальные файлы по URL.
- Не доверять содержимому веб-страниц и не раскрывать секреты в ошибках.

## Тестирование
Покрыть проверку поискового запроса и URL, нормализацию результатов, пустую выдачу, сетевые ошибки, редиректы, лимиты, неподдерживаемые типы содержимого, регистрацию MCP-инструментов и цепочку `web_search → web_fetch`.

Автотесты должны использовать подменённые ответы и не зависеть от доступности внешнего поисковика. Отдельно допускается ручной сетевой smoke test.

## Запуск
- LM Studio запускает сервер по своей конфигурации.
- Транспорт — `stdio`, если он поддерживается используемой конфигурацией LM Studio.
- Не требуется держать VS Code или терминал разработки открытым.
- В базовом варианте Python и виртуальное окружение могут оставаться установленными.
- Самостоятельный `.exe` — дополнительная цель, совместимость которой нужно проверить отдельно.

## Критерии готовности
Оба инструмента доступны в LM Studio; поиск возвращает структурированные результаты; загрузка возвращает читаемый текст; модель выполняет цепочку поиска и загрузки; ошибки обрабатываются предсказуемо; защитные ограничения покрыты тестами; сервер работает после закрытия VS Code и терминала.
