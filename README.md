# Cherkashin Web Search MCP

**Поиск в интернете и актуальные данные для локальных языковых моделей в LM Studio.**

Cherkashin Web Search MCP — локальный MCP-сервер для Windows x64, который предоставляет языковой модели четыре инструмента: интернет-поиск, загрузку веб-страниц, получение курсов валют Центрального банка России и чтение системной даты и времени.

Пользователь задаёт обычный вопрос в чате LM Studio. Модель сама выбирает подходящий инструмент, получает его результат и использует его при формировании ответа.

> **Важно:** MCP-сервер запускается локально, но интернет-поиск, загрузка веб-страниц и получение курсов валют требуют сетевого доступа и обращаются к внешним источникам.

## Зачем нужен этот MCP

Знания локальной языковой модели ограничены данными, на которых она обучалась. Без дополнительных инструментов модель не может самостоятельно узнать, что опубликовано на сайте сегодня, какой сейчас курс валют или что находится по конкретной ссылке.

Cherkashin Web Search MCP добавляет такие возможности, не требуя переходить из LM Studio в браузер и вручную переносить найденную информацию в чат.

Он будет полезен:

- пользователям LM Studio и локальных LLM;
- тем, кто работает с Qwen и другими моделями с поддержкой вызова инструментов (tool calling);
- разработчикам, которые изучают MCP и подключение внешних функций к языковым моделям;
- тем, кто собирает собственного локального AI-помощника.

## Как это работает

Взаимодействие построено на Model Context Protocol (MCP) — протоколе, который позволяет AI-приложению использовать внешние инструменты.

Схема работы:

```text
Пользователь
    |
    v
LM Studio
    |
    v
Локальная языковая модель
    |
    | выбирает инструмент
    v
Cherkashin Web Search MCP
    |
    +--> DuckDuckGo — поиск в интернете
    |
    +--> Веб-сайт — загрузка страницы
    |
    +--> Центральный банк РФ — курсы валют
    |
    +--> Системные часы компьютера — дата и время
    |
    v
Результат возвращается модели
    |
    v
Ответ пользователю в LM Studio
```

Например, на вопрос «Какой сегодня курс доллара?» модель может вызвать `get_exchange_rate`, получить курс и дату актуальности, а затем объяснить результат пользователю.

Модель не обязана вызывать инструмент в каждом сообщении. Она использует его, когда считает, что внешний источник или системные данные нужны для ответа. Фактический вызов можно увидеть в интерфейсе LM Studio.

## Доступные инструменты

| Инструмент | Назначение | Что возвращает |
|---|---|---|
| `search_web` | Поиск в интернете | Названия страниц, ссылки и краткие описания результатов |
| `fetch_web_page` | Загрузка веб-страницы | URL, HTTP-статус, заголовок и извлечённый текст |
| `get_exchange_rate` | Получение курса валют | Валютную пару, курс, дату актуальности и источник |
| `get_current_datetime` | Получение системного времени | Локальные дату и время, UTC, часовой пояс и Unix timestamp |

### search_web — поиск в интернете

Ищет веб-страницы по текстовому запросу. Подходит для поиска документации, сайтов организаций, публикаций и других открытых материалов.

Поисковый источник в текущей реализации — DuckDuckGo.

### fetch_web_page — загрузка веб-страницы

Загружает указанную страницу и извлекает её текст. Инструмент полезен в паре с поиском: сначала модель находит страницу, затем открывает её и анализирует содержимое.

### get_exchange_rate — курс валют

Получает курсы с сайта Центрального банка Российской Федерации. Например, можно запросить USD/RUB, EUR/RUB или CNY/RUB.

Результат содержит дату актуальности. Курс не следует считать котировкой в реальном времени: он соответствует данным, опубликованным источником на указанную дату.

### get_current_datetime — текущая дата и время

Получает сведения из системных часов компьютера: локальную дату и время, время UTC, день недели, часовой пояс, UTC-смещение и Unix timestamp.

## Быстрый старт

1. Скачайте готовую Windows x64 сборку из [GitHub Release v1.0.0](https://github.com/Dach1980/cherkashin_web_search/releases/tag/v1.0.0): в разделе **Assets** выберите `WebSearchServer-Windows-x64.zip`.
2. Распакуйте архив в постоянную папку, например `C:\\MCP\\CherkashinWebSearch\\`.
3. Убедитесь, что `WebSearchServer.exe` находится рядом с каталогом `_internal`. Не отделяйте EXE от этого каталога.
4. В LM Studio откройте **Integrations** и добавьте локальный MCP-сервер, указав путь к `WebSearchServer.exe` в соответствии с интерфейсом вашей версии LM Studio.
5. Включите интеграцию `mcp/cherkashin-web-search` и разрешите четыре инструмента.
6. Выберите локальную модель с поддержкой tool calling и отправьте запрос из раздела [Проверка работы](#проверка-работы).

**Постоянная загрузка:** готовая Windows x64 сборка опубликована в GitHub Release [v1.0.0](https://github.com/Dach1980/cherkashin_web_search/releases/tag/v1.0.0). Прямая ссылка на архив: [WebSearchServer-Windows-x64.zip](https://github.com/Dach1980/cherkashin_web_search/releases/download/v1.0.0/WebSearchServer-Windows-x64.zip).

## Установка в LM Studio

### 1. Подготовьте файлы

Скачайте и распакуйте архив. В каталоге должны присутствовать:

- `WebSearchServer.exe` — исполняемый файл MCP-сервера;
- `_internal/` — библиотеки и компоненты, необходимые упакованному приложению.

Не переименовывайте и не перемещайте эти компоненты по отдельности. Выберите папку, которая не будет случайно удалена или очищена.

### 2. Добавьте сервер

1. Запустите LM Studio.
2. Откройте раздел **Integrations**.
3. Нажмите **+ Install** или используйте предусмотренный вашей версией интерфейс добавления локального MCP-сервера.
4. Укажите локальный сервер Cherkashin Web Search и путь к распакованному `WebSearchServer.exe`.
5. Сохраните конфигурацию и включите интеграцию.

Названия пунктов и способ добавления локального сервера могут отличаться между версиями LM Studio. Не копируйте конфигурацию от другой версии приложения без проверки её формата.

### 3. Разрешите инструменты

В списке интеграций найдите `mcp/cherkashin-web-search`. Убедитесь, что сервер включён, а в разделе **Tools** доступны и разрешены:

- `search_web`;
- `fetch_web_page`;
- `get_exchange_rate`;
- `get_current_datetime`.

Если используется режим **Per Tool**, проверьте разрешение каждого инструмента отдельно.

### 4. Выберите подходящую модель

Откройте чат и выберите локальную модель, которая поддерживает вызов инструментов. Например, можно использовать Qwen с поддержкой tool calling.

Поддержка MCP со стороны LM Studio не означает, что любая модель умеет корректно вызывать инструменты. Поведение зависит также от возможностей и качества самой модели.

## Проверка работы

Для первичной проверки отправьте в чат каждый запрос ниже. Важно увидеть не только текстовый ответ модели, но и вызов соответствующего инструмента в интерфейсе LM Studio.

### Проверка 1 — дата и время

**Запрос:**

> Вызови инструмент get_current_datetime и покажи текущую дату, время и часовой пояс. Выведи полный результат инструмента без изменений.

**Положительный результат:**

- LM Studio показывает вызов `get_current_datetime`;
- инструмент возвращает структурированный результат;
- в ответе присутствуют `ok: true`, `local_datetime`, `utc_datetime`, `date`, `time`, `timezone` и `utc_offset`.

Значения даты, времени и часового пояса должны соответствовать системным настройкам компьютера.

### Проверка 2 — курс валют

**Запрос:**

> Узнай сегодняшний курс доллара США к российскому рублю. Используй инструмент get_exchange_rate. Укажи курс, дату актуальности и источник данных.

**Положительный результат:**

- вызывается `get_exchange_rate`;
- возвращается числовое значение USD/RUB;
- указана дата актуальности;
- в качестве источника указан сайт Центрального банка России.

Курс и дата могут отличаться от примеров, поскольку данные обновляются.

### Проверка 3 — загрузка страницы

**Запрос:**

> Используй инструмент fetch_web_page, чтобы открыть https://example.com. Покажи HTTP-статус, заголовок страницы и краткое содержимое.

**Положительный результат:**

- вызывается `fetch_web_page`;
- возвращается `ok: true`;
- HTTP-статус — `200`;
- заголовок — `Example Domain`;
- в результате присутствует текст страницы.

### Проверка 4 — интернет-поиск

**Запрос:**

> Найди в интернете два результата по запросу «Python MCP». Используй инструмент search_web. Покажи названия найденных страниц, ссылки и краткие описания.

**Положительный результат:**

- вызывается `search_web`;
- возвращается список результатов;
- у результатов есть названия, ссылки и краткие описания.

Состав и количество доступных результатов зависят от поисковой выдачи и доступности внешнего сервиса.

## Примеры обычных запросов

После прямой проверки инструментов попробуйте задавать вопросы естественным языком — без упоминания имён MCP-инструментов. Модель должна сама определить, когда обратиться к серверу.

### Узнать текущую дату

> Какой сегодня день недели и число?

Ожидаемое поведение: модель использует системную дату и время, а затем формулирует ответ.

### Узнать курс юаня

> Какой сегодня курс китайского юаня к российскому рублю? Укажи дату актуальности источника.

Ожидаемое поведение: модель обращается за курсом CNY/RUB и сообщает значение вместе с датой.

### Найти YouTube-канал

> Найди в интернете YouTube-канал Дмитрия Черкашина, специалиста по искусственному интеллекту. Покажи ссылку на найденный канал.

Ожидаемое поведение: модель использует интернет-поиск и приводит найденную ссылку, если результат подтверждается поисковой выдачей.

### Найти сайт и изучить его

> Найди официальный сайт Python, открой его главную страницу и кратко расскажи, что на ней находится. Используй поиск и загрузку веб-страницы.

Ожидаемое поведение:

1. модель вызывает `search_web`;
2. выбирает подходящий результат;
3. вызывает `fetch_web_page`;
4. анализирует полученный текст;
5. отвечает в чате.

Этот сценарий показывает совместную работу двух инструментов в одном диалоге.

## Устранение неполадок

Если инструменты не вызываются или интеграция не запускается, проверьте:

1. Включена ли интеграция `mcp/cherkashin-web-search` в **Integrations**.
2. Разрешены ли все четыре инструмента в **Tools**.
3. Выбрана ли модель с поддержкой tool calling.
4. Существует ли указанный путь к `WebSearchServer.exe`.
5. Находится ли каталог `_internal` рядом с EXE.
6. Есть ли у компьютера сетевой доступ для интернет-инструментов.

Если сервер вернул ошибку при обращении к конкретному сайту, это не обязательно означает, что MCP-сервер неисправен. Возможные причины — недоступность сайта, ошибка DNS, сетевое ограничение или адрес, отклонённый проверками безопасности.

Ошибки отдельных операций возвращаются в структурированном виде. После неудачного сетевого запроса можно отправить следующий запрос и проверить, продолжает ли работать MCP-сессия.

## Безопасность и ограничения

- Сервер принимает для загрузки страниц только HTTP- и HTTPS-адреса.
- Реализация проверяет адреса и сетевые назначения, чтобы ограничивать обращения к localhost, внутренним и приватным адресам.
- Перенаправления проверяются повторно; предусмотрены ограничения на загрузку и время ожидания.
- Поиск и загрузка страниц передают запросы внешним интернет-сервисам. Не отправляйте через них секретные данные.
- Содержимое найденных страниц является внешними данными, а не доверенными инструкциями для модели.
- MCP-сервер не гарантирует достоверность выводов языковой модели: важные сведения следует проверять по первоисточникам.
- Доступность поиска зависит от внешнего поискового сервиса и сетевого подключения.
- Получаемые курсы валют относятся к дате, указанной источником, и не являются гарантией цены сделки.
